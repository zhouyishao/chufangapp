# 鉴权规则

## 管理后台

- 使用 JWT Bearer Token。
- 登录接口：`POST /api/admin/auth/login`。
- 用户信息接口：`GET /api/admin/auth/profile`。
- 登录和资料响应均返回当前唯一有效角色与权限键；`SUPER_ADMIN` 返回 `*`，其他角色返回数据库中的有效权限。
- 每个管理员只允许一个有效角色；账号停用、角色停用、角色缺失或出现多个有效角色时，后续请求立即失效。
- 需要鉴权的管理接口先经过 `requireAdminAuth`，再由统一路由策略按请求方法校验查看、新增、编辑、发布/状态、删除或管理权限。
- 权限不只用于前端隐藏菜单和按钮；直接请求无权限 API 一律返回 HTTP 403。
- 权限每次请求从数据库实时读取，角色权限调整后，已登录 Token 无需重新登录即可在下一次请求生效。
- 管理员不能停用或删除自己；系统必须保留至少一个有效超级管理员；系统角色不可删除，在用角色不可停用或删除。
- 管理员、角色和权限变更写入操作日志，日志详情会递归移除密码、密码哈希、Authorization 和 Token。

## C 端

- MVP 采用后台开户制手机号密码登录：管理员在用户管理中设置手机号和初始密码。
- C 端登录只查询已有用户并校验 bcrypt 哈希，不允许按手机号自动创建账号。
- 当前不接入短信验证码；注册和自助找回密码页面明确显示暂未开放，由管理员开通或重置。
- 后续接入短信服务时，可在现有 `passwordHash` 模型上增加验证码注册与重置流程。
- 涉及收藏、浏览历史、家庭、采购记录的接口需要识别用户身份。

## 安全要求

- 不在代码中硬编码 JWT Secret。
- `.env` 不提交。
- `.env.example` 只保留字段名和示例值。
- Token 失效时前端必须跳转登录或提示重新登录。
- C 端密码使用 bcrypt 成本参数 10，仅保存哈希；API、日志、列表和详情禁止返回哈希或明文。
- 不存在账号与密码错误使用同一 401 文案，避免枚举手机号。
- 历史无密码账号和禁用账号返回 403，且不签发 App Token。

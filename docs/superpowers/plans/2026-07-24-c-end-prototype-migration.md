# 正式 C 端原型迁移实施计划

## 目标

把 `docs/prototypes/home-feed-interactive/` 中已经确认的交互原型，迁移到正式 `frontend/`。正式 C 端必须继续使用真实 API、鉴权、上传和后台配置；不把原型 HTML 直接复制到生产页面，也不再使用静态 mock 冒充真实内容。

完成后，用户从首页、分类、菜篮、我的进入五类详情与制作流程时，页面结构、信息层级、尺寸、交互方式与已确认原型一致；后台发布或下架内容会同步影响正式 C 端。

前端开发逐页实施时必须同时使用配套文档：

- [《正式 C 端原型迁移前端开发执行手册》](../../app/c-end-prototype-migration-frontend-guide.md)

## 强制边界

- 原型目录冻结，只读参考，禁止修改：`docs/prototypes/home-feed-interactive/`。
- 视觉迁移阶段只改 `frontend/`；确有 DTO 缺口时，先记录接口契约，再单独修改 `server/`，不得以硬编码数据绕过。
- 禁止修改历史 `backend/`、`admin-backend/`。
- 禁止清库、重置 Prisma migration 或删除既有 C 端路由。
- 每个页面先接真实数据，再做视觉；不得先写一张无法联调的静态页面。
- 不改变已确认规范：393pt 设计宽度、iPhone 15 安全区、首页 Banner 393×420、详情主图左右和顶部顶满、底部导航四项（首页/分类/菜篮/我的）。
- 液态玻璃仅保留在底部导航、必要的悬浮顶栏与弹层；普通内容卡不使用毛玻璃。

## 视觉基线

### 全局

- 使用 `frontend/src/styles/global.scss` 的现有 Token；新增 Token 也只能写入此文件。
- 系统字体：`-apple-system, BlinkMacSystemFont, "SF Pro Text", "SF Pro Display", "PingFang SC", "Helvetica Neue", Arial, sans-serif`。
- 主色 `#7A8B6F`；背景 `#F5F1EA`；表面 `#FFFDFC`；正文 `#2F2F2F`。
- 普通卡片使用较小圆角、清晰留白和弱分隔；禁止“高圆角 + 大阴影 + 玻璃”的叠加。
- 所有图标使用统一线性/面形规则：未选中线性，选中面形；不可出现文字与图标不在同一视觉基线的问题。
- 所有固定操作区和底部导航必须适配 `env(safe-area-inset-bottom)`；正文预留完整底部高度。

### 图片与卡片

- 首页 Banner：`393 × 420`，满宽，不允许再改高。
- 首页菜谱横滑卡：正方形图片；一屏露出约 2.5 张；图片与卡片上、左、右无空隙；文字区只保留名称、时长、难度和右上收藏。
- 时令果蔬：正方形小图，内容轻量，不写冗余描述。
- 分类双列内容：正方形图片；名称与月份一行，价格和菜篮图标一行；菜篮图标固定右下，不得被裁切。
- 全部详情主图：自适应满宽，设计基准约 `852 × 844px`，顶部和左右顶满，不保留外边距。

### 响应式尺寸计算

- 所有视觉尺寸以 393pt 设计稿为基准，不把 393px 下的固定高度直接复制到所有设备。
- 首页 Banner 在 393px 宽度下固定为 393×420；其他宽度使用 `aspect-ratio: 393 / 420` 等比缩放，禁止在 360、375、430px 下仍强制写死 420px 高度。
- 五类详情页主图使用已确认的约 852×844 比例，左右、顶部顶满；通过统一 `aspect-ratio`、`object-fit: cover` 和焦点位置字段适配不同屏幕。
- 正方形内容图片必须由容器比例控制，不允许依赖图片原始尺寸撑开布局。
- 100%–200% 字体缩放时，文字区域由内容自然撑开；不得压缩主图比例、截断关键文案或让按钮移位。
- 360、375、393、430px 四档宽度均不得出现横向滚动、内容裁切和底部导航遮挡。

### 页面状态矩阵

每个正式页面在实现前必须明确并验证以下状态，不允许只迁移“有数据的理想截图”：

- 身份：未登录、已登录、Token 失效。
- 家庭：未加入家庭、普通成员、管理员、创建者。
- 数据：加载中、正常、空数据、分页结束、弱网、请求失败、重试成功。
- 权限：可查看、可编辑、无权限、内容已下架。
- 操作：已收藏/未收藏、已加入菜篮/未加入、重复点击、提交中。
- 媒体：图片加载失败、视频加载失败、视频格式不支持。
- 内容：已发布、未发布、已下架、审核不通过、深链目标不存在。

状态组件应优先复用统一实现，页面不得自行硬编码不同风格的加载、空态和错误提示。

## 阶段 -1：现有修改安全基线

### 目的

当前正式 C 端、后端和后台已有未提交或未完整验收的修改。正式迁移开始前先保护已有成果，避免新迁移覆盖可用代码、把临时实现带入发布版本，或因回退整页而丢失其他改动。

### 执行内容

1. 只读审计当前工作区全部 diff，并按以下类型分类：
   - 可直接保留；
   - 需要验证后保留；
   - 与本计划冲突；
   - 临时文件、构建产物或调试代码；
   - 涉及接口、Schema、migration 的未完成实现。
2. 检查敏感信息、临时 URL、硬编码用户 ID、mock 数据、重复组件、死路由和不完整 migration。
3. 记录当前 `frontend/`、`server/`、`admin-frontend/` 的构建与测试结果，失败项必须区分为既有问题和本次新增问题。
4. 可保留成果按语义拆分为基线提交；禁止覆盖、丢弃或批量格式化用户已有改动。
5. 建立“页面—路由—接口—DTO—后台字段—数据表”追踪矩阵，并标记每一项当前状态。
6. 建立旧页面、旧组件、旧 DTO、mock、localStorage 和硬编码内容清单，为后续逐页替换提供删除依据。

### 阶段门槛

- 所有未提交修改都有明确归属。
- 不存在未识别的敏感信息、破坏性 migration 或临时构建产物。
- 当前可运行基线和已知失败已记录。
- 未经审计，不进入正式页面替换。

## 阶段 0.5：API/DTO 与测试数据冻结

### 目的

避免页面迁移过程中同时兼容多套旧字段，或因接口持续变化导致页面反复返工。该阶段只冻结正式 C 端消费的契约和测试数据，不进行视觉改造。

### 工作项

1. 为每个正式页面建立“路由—页面 DTO—服务函数—后端接口—后台配置字段”映射。
2. 标记字段状态：已提供、字段名不一致、类型不一致、缺失、旧字段兼容、计划移除。
3. 页面组件只消费页面 DTO；历史字段和接口差异统一在 `frontend/src/services/` 适配，禁止散落到页面模板。
4. 公共 DTO、Schema 和 migration 由单一负责人修改；契约冻结前不并行改后端、后台和 C 端同一字段。
5. 记录旧接口和旧字段的兼容窗口；新页面稳定前不得一次性删除旧字段。
6. 准备稳定的联调账号和种子数据：
   - 普通用户、家庭管理员、家庭创建者；
   - 无家庭、单家庭、多家庭；
   - 有内容、空内容、已下架内容；
   - 普通饮品、可调制饮品；
   - 纯文字步骤、图片步骤、视频步骤、带计时器步骤。
7. 联调和截图不得依赖某位开发者个人账号中的临时数据。

### 阶段门槛

- 所有计划迁移页面都有明确 DTO 和接口来源。
- 页面不需要自行判断多套历史字段。
- 缺失字段已形成独立接口任务，禁止用 mock 或临时常量绕过。
- 稳定测试账号和最小种子内容可重复使用。

## 阶段 2：首页迁移（先做，作为视觉样板）

### 修改范围

- `frontend/src/pages/index/index.vue`
- `frontend/src/components/home/`
- 首页已有真实服务层；仅在 DTO 不足时新增 `server/` 接口字段

### 锁定结构

1. 顶部：轻透搜索框与独立铃铛同一行；频道在搜索框下。
2. 频道：推荐/菜谱/食材/水果/饮品；上滑后搜索框隐藏，频道固定且不能从左右滑入。
3. Banner：393×420，频道切换时同时切换对应 Banner 和内容；后台可配置多张轮播。
4. 推荐流固定起始顺序：
   - 时令果蔬。
   - 家常精选。
   - 挑选指南/当季食材。
   - 继续发现（相似菜谱、同食材菜谱、饮品搭配）。
5. 普通模块标题只显示标题和“查看更多”；不增加无意义小标题。
6. 家常精选、今天吃什么等菜谱模块统一为正方形横滑卡，一屏约 2.5 张。
7. 选择指南、当季食材、关联食材统一为“左图右文”的单一模块，不使用箭头，不堆叠标签。

### 真实数据要求

- Banner、频道、模块顺序、上下架和内容来源全部由后台驱动。
- 支持分页、加载中、加载失败重试、结束态；无内容显示真实空态。
- 频道切换只刷新当前频道数据，不回退到 mock。

### 验收

- 393px 首屏与确认原型对齐：Banner 尺寸、搜索、频道、时令果蔬和底部导航不偏移。
- 首页连续浏览至少 6 屏，但连续模块构图不机械重复。
- Banner、频道、卡片、查看更多、收藏、加入菜篮均有真实反馈。

### 锁定结构

1. 菜篮顶部是“菜篮”、当前家庭下拉与扫一扫入口；不显示手机状态栏图形。

   - 食材视图合并相同物品。
   - 菜谱视图可展开每道菜的食材。

### 真实数据要求

- 全部家庭/菜篮/成员操作以当前 JWT 用户与家庭权限校验。

### 验收

- 普通成员无法改家庭头像、删成员或改管理员权限。
- 家庭切换后菜篮和偏好同步更新。

- 菜谱：标题/时长/难度/份量/家庭忌口提示；食材、步骤、小贴士；食材用紧凑网格模块；步骤支持文字、图片、视频、计时和小贴士；底部为相似菜谱、同食材菜谱、搭配饮品。
- 食材/水果：季节、约多少钱一斤、怎么挑、怎么放、怎么吃、相关菜谱。
- 饮品：普通饮品仅展示基础信息；可调制饮品额外展示基酒、辅料、器具、制作步骤与“去制作”。
- 调料：用途、常见搭配、参考价格、相关菜谱。
- 制作流程：当前步骤、总进度、上一步/下一步、计时器开始/暂停/重置、最后一步完成态；步骤媒体失败时仍显示文字。

### 验收

- 任一详情都可深链进入并返回正确列表位置。
- 收藏、菜篮、制作、计时器和相关推荐均使用真实接口/真实数据。
- 普通饮品不出现调酒字段；可调制饮品可完整进入制作流程。
- 从列表、搜索、首页推荐、通知和扫码入口进入详情时，返回行为符合来源上下文。
- Token 失效登录成功后能回到原目标；不得返回已废弃页面或丢失必要参数。
- 从详情返回横滑列表或长列表时恢复原滚动位置。

## 性能与媒体预算

- 首页首屏只优先请求当前频道必需数据；非当前频道在用户切换后加载，不抢占首屏带宽。
- Banner 首张图允许优先加载；非首屏内容和后续轮播图使用延迟加载。
- 所有图片容器声明宽高或比例，避免加载前后布局跳动。
- 图片按显示尺寸请求合适规格，禁止小卡片直接下载原始超大图。
- 视频不自动播放，不在列表页预加载完整文件；弱网时优先展示封面和文字步骤。
- 滚动动画仅使用 `transform` 和 `opacity`；大面积滚动内容禁止 `backdrop-filter`。
- 保留 RAF 滚动节流、IntersectionObserver 或平台等价实现；禁止为视觉效果注册高频无节流滚动监听。
- 每个阶段记录首屏请求数量、主要图片体积、首屏可操作时间和低性能 Android 滚动表现；指标退化必须解释并修复。

# 家里有菜 C 端全页面重构设计

## 1. 文档状态

- 日期：2026-07-11
- 范围：`frontend/` 全部 C 端页面及其配套接口能力
- 当前阶段：产品结构与交互设计确认
- 实施约束：设计确认前不修改业务页面代码

本文件替代此前已经推翻的首页视觉原型方向。后续原型、实施计划和验收均以本文件为准。

## 2. 产品定位

“家里有菜”不是单纯的菜谱浏览器，而是围绕家庭成员、饮食偏好、聚餐菜单、采购和烹饪形成闭环的家庭饮食 App。

产品需要回答四个问题：

1. 今天吃什么？
2. 这顿饭还需要准备和采购什么？
3. 参与吃饭的人有哪些忌口和喜好？
4. 选好菜单后怎样顺利采购和制作？

内容体系包括：

- 菜谱。
- 普通食材与调料。
- 水果。
- 饮品。
- 未来的调酒内容。

## 3. 后端现状与领域边界

当前真实数据结构决定了以下边界：

- 菜谱使用 `Recipe`，并通过 `RecipeIngredient` 关联食材。
- 普通食材、水果和调料使用 `Ingredient`，通过 `Category.type` 区分 `INGREDIENT`、`FRUIT`、`SEASONING`。
- 饮品使用独立的 `Beverage` 模型。
- 菜谱通过 `RecipeBeverage` 关联推荐饮品。
- `Beverage` 已具备基酒、杯型、配料、用量、装饰和调制步骤等调酒字段。
- 家庭成员和家庭偏好已有基础模型，但聚餐、参与成员、菜单冲突和提醒能力仍需补充设计与实现。

后续实现前需要补齐的关键接口或模型能力：

- 饮品列表与筛选接口。
- 食材列表按普通食材、水果、调料分类筛选。
- 饮品详情返回完整调制字段。
- 推荐内容对饮品目标的直接关联。
- 家庭聚餐、参与成员、菜单、到场状态和开饭提醒。
- 过敏原、忌口、不喜欢、喜欢、口味和饮品偏好的结构化表达。
- 未来把饮品配料从纯 JSON 逐步关联到正式食材，以支持规范的配料展示、单位换算和菜篮联动。

### 3.1 标准食材与风险匹配

家庭忌口检查不能依赖菜谱中的自由文本。实施时需要建立标准食材、别名和风险标签关系：

```text
标准食材：花生
├── 花生米
├── 花生碎
├── 花生酱
├── 落花生
└── 花生粉
```

- 菜谱用料优先关联正式 `Ingredient.id`。
- 临时文本用料必须经过别名识别，再参与过敏和忌口检查。
- 标准食材需要支持上级原料、过敏原、替代食材和风险标签。
- 无法识别的用料必须标记“未完成风险检查”，不能静默视为安全。

### 3.2 安全边界

- 过敏原属于强安全限制，默认阻止进入家庭菜单。
- 忌口属于明确排除，但允许管理员确认调整。
- 不喜欢属于软提醒，可通过少放、后放或分开制作处理。
- 喜好只影响推荐排序，不影响安全判断。
- 少盐、低糖等制作要求需要落实到用量和具体步骤。
- 产品需要声明饮食提示用于辅助检查，不能替代医疗建议。
- 后台内容需要支持标记潜在过敏原和交叉污染风险。

## 4. 一级导航

底部一级导航固定为：

```text
首页｜分类｜菜篮｜我的
```

底部不增加消息入口，不建设聊天、私信或群聊功能。

### 首页

解决当天家庭饮食决策，融合菜谱、食材、水果、饮品和家庭状态。

### 分类

负责完整结构化目录和明确查找，不展示首页推荐流。分类目录包括菜谱、普通食材、水果、调料和饮品。

### 菜篮

负责家庭采购准备和聚餐采购清单，不定义为普通购物车。用户侧文案统一使用“菜篮”。

### 我的

负责个人资料、饮食档案、家庭、收藏、历史、个人菜谱和设置。

## 5. 首页结构

首页不展示传统页面标题、家庭选择、日期、节气或问候语。顶部只保留搜索入口和通知入口。

```text
搜索入口                              通知
推荐｜菜谱｜食材｜水果｜饮品
简洁主 Banner
今天吃什么
当季值得吃
当季食材与水果
今晚菜单与饮品搭配
家庭聚餐或采购状态
底部导航
```

### 首页顶部

- 搜索框与通知铃铛位于同一行，搜索框占据剩余宽度，两者等高并垂直居中。
- 首页顶部不显示家庭切换、日期、节气、问候语、Logo 或页面标题。
- 首页频道位于搜索行下方。
- 搜索行和频道均属于页面内容，不在初始状态永久固定。
- 首页频道固定为“推荐｜菜谱｜食材｜水果｜饮品”。
- “推荐”汇总跨类型精选；其他频道展示对应类型的内容流。
- 首页“食材”只展示普通食材，不包含水果、调料和饮品。

### 搜索栏滚动行为

```text
初始：完整显示搜索栏
向上滑动：搜索栏随内容自然离场
继续滚动：首页五频道导航吸顶
向下回滑：搜索入口逐渐恢复
回到顶部：恢复完整搜索栏
```

- 不使用厚重纯白胶囊。
- 不突然改变高度造成页面跳动。
- 使用轻表面、极弱边缘高光和清晰触控区域。
- 扫码入口与搜索框分开，避免把扫码误认为搜索功能。

## 6. 首页频道与分类页

### 首页推荐频道

推荐频道最多包含：

```text
进行中的家庭聚餐（存在时优先）
1 个简洁主 Banner
今日菜谱
当季食材与水果
推荐饮品
```

首页推荐最多四个常规内容模块。每个模块只展示少量内容，通过“查看全部”切换到对应首页频道，不允许后台无限追加模块。

### 首页菜谱频道

```text
推荐｜家常｜快手｜时令｜菜系｜口味｜场景
```

### 首页食材频道

```text
推荐｜时令｜蔬菜｜肉禽｜水产｜菌菇｜豆制品｜米面粮油
```

首页食材频道不展示水果和调料。

### 首页水果频道

```text
推荐｜当季｜柑橘｜浆果｜瓜果｜热带｜核果｜仁果
```

### 首页饮品频道

```text
推荐｜无酒精｜水与气泡水｜茶与咖啡｜果汁｜酒类｜餐食搭配
```

未来增加“调一杯”，但不占底部一级导航。

### 分类页

分类页不展示 Banner、推荐流和运营内容，只提供五组完整目录：

```text
菜谱目录
食材目录
水果目录
调料目录
饮品目录
```

- 菜谱：按做法、场景、口味、时间、菜系等查找。
- 食材：蔬菜、肉禽、水产、菌菇、豆制品、米面粮油等。
- 水果：当季、柑橘、浆果、瓜果、热带、核果、仁果等。
- 调料：基础调味、提鲜、辛香、腌制、烘焙、蘸料、火锅和西式香料等。
- 饮品：无酒精、水与气泡水、茶与咖啡、果汁、酒类和餐食搭配等。

点击具体分类后进入纯结果列表，不在分类页继续无限展开。首页频道和分类结果页分别保留筛选与滚动位置。

## 7. Banner 规范

Banner 必须简单、大气，每张只表达一个主题。

允许：

- 一张高质量主图。
- 一个最多两行的短标题。
- 一句可选说明。
- 整张 Banner 作为一个点击目标。

禁止：

- 多个操作按钮。
- 大量标签和统计信息。
- 玻璃卡片叠加。
- 密集轮播点。
- 过快自动轮播。

Banner 可承载菜谱、时令食材、水果、饮品、家庭菜单或运营活动。

## 8. 列表与详情体系

所有详情页禁止把完整信息从上到下直接平铺。统一使用：

```text
顶部导航
主视觉与核心摘要
家庭适配提醒
吸顶分段导航
当前分段内容
固定底部主要操作
```

- 主视觉滚出后，分段导航吸顶。
- 每次只展示当前分段的主要内容。
- 长说明默认展示 3–5 行，通过“展开”查看全文。
- 相关内容每组首屏最多展示 4–6 项，优先横向浏览。
- 完整数据、价格历史等低频信息进入二级页面或底部面板。
- 从关联详情返回时恢复原分段和滚动位置。
- 烹饪和调制步骤使用独立专注模式，不在详情页完整铺开。

### 菜谱

列表卡片展示图片、名称、时间、难度、少量标签和收藏状态。

详情结构：

```text
主图与名称
时间 / 难度 / 份量
家庭适配状态
概览｜用料｜步骤｜搭配
收藏｜加入菜篮｜开始烹饪
```

- 概览：简介、家庭适配、技巧摘要和前 3 项食材预览。
- 用料：完整食材、份量调整、忌口提示、选择和批量加入菜篮。
- 步骤：只显示步骤目录和简短摘要，主要操作为“开始烹饪”。
- 搭配：推荐饮品和相关菜谱，使用横向内容列表。

### 食材

食材包括普通食材和调料。

普通食材详情使用：

```text
怎么挑｜参考价格｜保存食用｜相关菜谱
```

- 怎么挑：外观、手感、气味、新鲜度、应避开的问题，以及好坏对比图片或短视频。
- 参考价格：当前参考价、常见价格区间、更新时间、来源和数据充足度。
- 保存食用：保存方式、营养摘要、食用禁忌和家庭适配。
- 相关菜谱：少量横向推荐、搭配食材和“查看全部”。

价格统一标注“参考价”和“仅供参考”。价格判断只能使用“偏低、常见、偏高、数据不足”，并同时显示地区、时间、单位、来源和样本情况；不得把参考价格表达为成交价或购买建议。

调料详情使用：

```text
概览｜使用方法｜相关菜谱
```

- 概览：调料类型、风味、家庭风险和参考价格。
- 使用方法：推荐用量、适合烹饪方式、添加时机、替代调料和保存方式。
- 相关菜谱：少量横向菜谱和“查看全部”。

### 水果

水果独立为首页一级频道，但复用食材基础数据。

详情结构：

```text
主图与名称
当季时间
怎么挑｜参考价格｜成熟保存｜菜谱饮品
加入菜篮
```

- 怎么挑：根据“今天吃、放两三天、需要久放”给出外观、手感、气味和成熟度建议。
- 参考价格：按品种、产地、等级、包装规格和标准单位展示常见区间，并明确仅供参考。
- 成熟保存：成熟度、预计适食时间、催熟或冷藏建议、营养摘要和家庭适配。
- 菜谱饮品：相关菜谱与相关饮品各展示少量横向内容。

水果同时连接菜谱、果汁饮品和未来调酒。

### 饮品

基础饮品详情使用：

```text
概览｜饮用说明｜搭配
```

- 概览：类别、风味、是否含酒精、酒精度和适合场景。
- 饮用说明：适饮温度、饮用方式和注意事项。
- 搭配：推荐菜谱、相关水果和相似饮品。

可调制饮品使用：

```text
概览｜材料｜调制｜搭配
```

- 材料：配料、用量、水果和加入菜篮。
- 调制：杯型、冰块、调制方式和步骤目录，完整流程进入“开始调制”。
- 搭配：推荐菜谱、相关水果和相似饮品。

## 10. 家庭与饮食档案

### 家庭加入

创建家庭后生成家庭二维码。加入家庭的主要方式是扫码。

```text
扫码
→ 验证二维码
→ 展示家庭名称和创建者
→ 登录（如需要）
→ 用户确认加入
→ 引导填写饮食档案
```

二维码支持有效期、失效、刷新、分享和保存。

### 饮食档案

每位成员维护：

- 过敏原：强安全限制。
- 忌口：明确不吃。
- 不喜欢：软提醒，可通过分开处理解决。
- 喜欢：用于推荐排序。
- 口味偏好：清淡、少盐、辣度等。
- 饮品偏好：无酒精、低糖等。

家庭成员之间可直接查看具体姓名和饮食信息，不做匿名汇总。

新成员扫码加入后先完成快速建档：

```text
是否有过敏原？
明确不吃什么？
是否饮酒？
```

其他喜好可以稍后补充，避免首次加入流程过长。

### 风险等级

- 红色：过敏原或明确忌口，默认阻止加入聚餐菜单。
- 橙色：不喜欢或可以调整，例如香菜单独放。
- 绿色：适合所有参与成员。

状态不能只依赖颜色，必须同时显示文字和图标。

### 家庭权限

| 操作 | 创建者 | 管理员 | 成员 |
|---|---:|---:|---:|
| 邀请成员 | ✓ | ✓ | — |
| 移除成员 | ✓ | ✓ | — |
| 编辑自己的饮食档案 | ✓ | ✓ | ✓ |
| 帮其他成员维护档案 | ✓ | ✓ | — |
| 发起聚餐 | ✓ | ✓ | ✓ |
| 修改他人创建的菜单 | ✓ | ✓ | 仅建议 |
| 发送开饭提醒 | ✓ | ✓ | — |
| 解散家庭 | ✓ | — | — |

管理员为老人或儿童维护饮食档案时，需要记录最后修改人和修改时间。

## 11. 家庭聚餐

家庭主页包括成员、饮食档案、发起聚餐、进行中的聚餐、家庭菜篮、家庭二维码和设置。

发起聚餐时填写：

- 名称。
- 日期和时间。
- 参与成员。
- 预计人数。
- 用餐场景。

选择参与成员后立即汇总本次饮食限制。未参与本次聚餐的成员不影响本次菜单判断。

聚餐状态：

```text
计划中 → 选择菜谱
菜单确定 → 生成采购清单
采购中 → 检查冲突和替代方案
准备制作 → 再次确认参与成员忌口
制作中 → 进入烹饪流程
开饭 → 管理员可发送开饭提醒
结束
```

### 聚餐变更处理

任何影响安全、菜单或采购的变化都生成“待处理事项”，由创建者或管理员确认，禁止系统静默修改。

- 新成员加入聚餐后，重新检查全部菜谱和饮品。
- 成员新增过敏原后，立即标记当前菜单冲突，并阻止继续确认采购或制作。
- 菜谱从菜单移除后，询问关联采购项是删除还是保留。
- 已完成采购后替换菜谱，需要列出多买和新增缺少的食材。
- 采购中修改参与人数时，重新计算份量并展示变化差异。

### 家庭聚餐首页优先级

存在进行中的家庭聚餐时，首页优先展示聚餐状态卡，高于普通运营 Banner：

```text
周末家庭晚餐
周六 18:30 · 6人
菜单 4道
采购 8/12
饮食提醒 2项
```

### 家庭适配结果

菜谱不使用无法解释的抽象分数，直接展示：

```text
适合全家
需要调整 1 项
不适合 2 位成员
```

点击后必须看到具体成员、冲突原料和处理建议。

## 12. 菜篮与采购

菜篮必须绑定当前家庭，不存在个人菜篮。家庭内所有成员共享查看和协作采购。

菜篮按采购状态组织：

```text
待采购｜已采购
```

“已采购”是当前菜篮任务的完成状态，不承担家庭库存、余量或保质期管理。已采购内容可在本次采购记录中查看，完成聚餐或主动归档后进入采购历史。

### 家庭切换

菜篮顶部明确显示当前家庭，并支持切换：

```text
张家菜篮 ▼
```

- 切换家庭后加载对应家庭的菜篮、聚餐、采购进度和采购历史。
- 每个家庭分别保存菜篮内容、筛选、分组和滚动位置。
- 底部菜篮角标只统计当前家庭的待采购数量。
- 切换时退出批量编辑状态；网络失败时继续保留原家庭内容。
- 正在生成聚餐采购清单或烹饪时，切换家庭需要明确确认退出当前流程。
- 无家庭状态提供“创建家庭”和“扫一扫加入”，不能创建个人菜篮。
- 用户从详情发起加入操作后才发现无家庭时，系统保存原始意图；成功创建或加入家庭后继续完成添加。

### 家庭共享

- 所有家庭成员可看到新增、数量变化和采购状态。
- 采购项记录添加人、来源、数量、单位和状态。
- 同一内容由多位成员或多个菜谱加入时合并数量并保留全部来源。
- 日常采购与聚餐采购可筛选查看，但属于同一个家庭菜篮。
- 家庭之间的数据不得自动合并；未来如需复制必须作为显式操作。

### 加入反馈

从菜谱、食材、水果、调料或饮品详情加入时，默认直接写入当前家庭，不额外弹出确认面板。成功后使用短 Toast：

```text
已加入「张家」菜篮
已合并到「张家」菜篮
数量已更新
```

- Toast 约 1.5–2 秒自动消失，不遮挡底部操作。
- 连续添加时合并提示，禁止多个 Toast 堆叠。
- 加入失败显示“加入失败，请重试”。
- 切换家庭后显示“已切换到「家庭名称」”。
- 无家庭、过敏原和忌口冲突不能只用 Toast，必须使用可操作面板或明确警告。

采购项按来源组织：菜谱、饮品与水果、用户单独添加。

生成采购清单前必须：

1. 合并重复食材。
2. 根据参与成员检查过敏和忌口。
3. 应用替代方案或分开处理方案。
4. 移除明确不采购的内容。
5. 生成最终数量和单位。

例如：

- 香菜：不采购、少量采购并单独放、保持原菜谱。
- 花生过敏：默认移除并建议替换菜谱或使用安全替代品。

同一食材从多个菜谱加入时合并数量，但保留来源。

### 菜篮内容跳转

- 点击普通食材名称进入食材详情。
- 点击水果名称进入水果详情。
- 点击调料名称进入调料详情。
- 点击饮品名称进入饮品详情。
- 点击采购项的来源菜谱名称进入菜谱详情。
- 修改数量、勾选和删除使用独立操作区，不与名称点击区域重叠。
- 从详情返回后恢复原菜篮分组、勾选状态和滚动位置。

### 数量与单位

- 菜谱份数变化后重新计算采购量。
- 系统定义标准单位和明确可换算关系。
- 可换算项目自动合并，例如汤匙与毫升。
- 无法可靠换算的项目并列展示，不猜测包装数量。
- 用户手动修改后的数量优先级高于系统自动计算。
- 第一阶段只实现可信的基础换算，不建设复杂包装推荐引擎。

## 13. 烹饪模式

烹饪采用单步骤推进，不显示底部主导航。

```text
退出烹饪
连续进度条
第 2 步 / 共 6 步
步骤图片
步骤标题与说明
本步骤用料
计时器
上一步｜下一步
```

### 进度

- 点击下一步推进进度。
- 返回上一步不丢计时状态。
- 中途退出保存当前步骤。
- 最后一步完成后进入完成状态。

### 计时器

- 未开始、计时中、暂停、继续、时间到、延长时间。
- 离开页面后仍保留计时。
- 时间到提供声音、震动和系统通知。
- 可同时保留多个步骤计时任务。
- 时间到不能自动跳转下一步。

### 忌口提醒

开始烹饪前显示本次参与成员的饮食汇总。

具体步骤命中偏好时局部提醒，例如：

```text
妈妈不喜欢香菜
建议先盛出一份，再加入香菜
```

### 长辈与无障碍

- 烹饪模式使用更大的正文、按钮和计时数字。
- 支持系统字体放大，不因文字变大遮挡下一步按钮。
- 计时结束同时提供声音、震动和视觉反馈。
- 过敏和忌口警告不能使用低对比小字。
- 颜色之外必须提供文字和图标说明。
- 支持系统“减少动态效果”设置。

## 14. 未来“调一杯”

入口位于饮品频道、饮品详情或水果详情，不增加底部导航。

```text
选择已有材料
→ 选择口味和酒精偏好
→ 查看可调饮品
→ 确认材料和用量
→ 分步骤调制
→ 完成
```

调制流程复用烹饪模式的进度和计时能力，并增加杯型、冰块、材料顺序、摇和/搅拌/直调和装饰信息。

## 15. 通知中心

通知中心在第二期上线。上线后，通知入口位于首页顶部右侧，使用铃铛图标和未读圆点或数量；第一期不展示无功能的通知图标。底部始终不增加消息入口。

通知分为：

```text
家庭｜系统｜活动
```

家庭通知：聚餐邀请、菜单重要变化、忌口冲突、采购任务和管理员发送的“开饭了”。

系统通知：菜谱审核、账号安全、必要的服务或隐私变化。

活动通知：时令专题、节日菜单、饮品专题、新功能和官方活动。

通知只支持查看、已读、删除和全部已读，不支持回复、评论、转发或表情互动。

### 开饭提醒

- 只有家庭创建者或管理员可以发送。
- 只发送给本次聚餐参与成员，不发送给“不参加”的成员。
- 发送内容固定简短，不允许演变成长文本聊天。
- 支持系统推送和 App 内通知。
- 发送后有冷却时间，并在聚餐页面保留发送记录。

## 16. 搜索与扫码

统一搜索结果支持：

```text
全部｜菜谱｜食材｜水果｜饮品
```

搜索继承进入频道的范围，并在返回时恢复关键词、筛选和滚动位置。

扫码当前主要识别家庭二维码，未来可扩展食材条码、饮品条码和菜谱分享二维码。扫码结果必须先验证类型和有效性，不能直接执行高影响操作。

## 17. 登录与用户资产

未登录用户可以浏览和搜索。收藏、菜篮、家庭、饮食档案、聚餐和创建菜谱需要登录。

登录流程必须记录原始意图：登录成功后返回原页面并继续原操作。

### 我的

```text
个人资料
当前家庭
我的饮食档案
收藏
浏览历史
我的菜谱
采购历史
家庭管理
设置
```

收藏和历史支持菜谱、食材、水果、饮品类型筛选。

创建菜谱按基本信息、食材用量、步骤、媒体和预览分段编辑，并自动保存草稿。步骤可记录建议时间，为烹饪计时器提供数据。

### 我的菜谱与添加菜谱

“我的”页面明确展示“我的菜谱”和“添加菜谱”入口。我的菜谱分为草稿、审核中、已发布和未通过。

创建或编辑菜谱时选择可见范围：

```text
仅自己可见
家庭可见
公开发布
```

- 草稿默认仅自己可见。
- 家庭可见菜谱无需公开审核，可参与家庭聚餐、忌口检查、采购清单和烹饪流程。
- 公开发布菜谱需要后台审核，通过后才可进入首页和分类公开内容。
- 家庭菜谱可在后续自愿提交为公开菜谱。
- 未识别的自由文本食材必须提示风险检查不完整。
- 添加菜谱使用分段编辑和自动保存，离开后可以继续。

## 18. 顶部导航

只保留三种模板：

1. 首页状态栏：搜索框和通知铃铛同一行；其下为首页五频道。
2. 首页频道/分类导航：首页五频道、分类目录和必要筛选。
3. 详情/子页面导航：返回、滚动后标题、一个主要右侧操作。

规则：

- 返回永远在左侧。
- 标题不能被右侧按钮挤偏。
- 右侧通常只保留一个操作，最多两个。
- 完整搜索栏不永久吸顶。
- 图片滚出后才显示详情标题。
- 不使用随意的超大 `z-index`。

## 19. 视觉系统

方向：编辑式内容排版、克制的生活温度、清晰的科技精度和少量高级液态玻璃。禁止用大圆角、暖色雾化和卡片堆叠制造所谓“高级感”。

### 已确认首页视觉基准

首页采用用户确认的 A 方案（明亮编辑感）作为唯一视觉基准，后续不再混用深色电影风或银白科技风：

- 顶部为自然日光、低饱和、全宽铺满的菜品 Banner。
- 搜索框与铃铛同一行，五频道位于搜索行下方，均覆盖在 Banner 顶部区域。
- Banner 下进入明亮中性内容区，不延续整页深色背景。
- 菜谱属于高信息内容，使用“一条重点推荐 + 两条轻量备选”的主次结构。
- 菜谱模块标题统一使用“今天吃什么”，不使用含义模糊的“今日灵感”。
- 时令蔬果属于低信息内容，使用小尺寸横向索引；一排显示 4 项并露出下一项，不展示冗长描述。
- 首页整体依靠图片裁切、字体层级、细分隔和留白形成精致感，不依赖卡片、阴影或夸张圆角。

基础色沿用：

- 背景 `#F5F1EA`。
- 主表面 `#FFFDFC`。
- 主文字 `#2F2F2F`。
- 品牌绿色 `#7A8B6F`。
- 弱分隔 `#E9E2D6`。
- 温暖橙只做少量点缀。

字体遵循项目全局系统字体和既有字号 Token。

### 视觉原型硬约束

视觉原型必须使用 Figma、HTML/CSS 或真实前端字体排版。生成式图片只用于无文字的菜品、食材、水果和饮品素材，不允许用图片模型生成最终 UI 文字、图标或组件。因此，生成式效果图中的中文字形、字号和位置不能作为设计验收依据。

#### 字体

- 全部界面文字使用系统字体栈，不使用图片内嵌字体，不混用宋体、衬线体或装饰字体。
- 首页频道与搜索文字：17pt / 500 / 24pt；选中态 600，不放大字号。
- Banner 标题：24px / 600 / 32px，最多两行；禁止超过 28px。
- Banner 辅助文案：15pt / 400 / 22pt，最多一行。
- 模块标题：22pt / 600 / 30pt。
- 菜谱与主要内容标题：18pt / 500 / 26pt。
- 正文与推荐理由：17pt / 400 / 25pt。
- 时间、难度、来源等辅助信息：15pt / 400 / 22pt。
- 时令果蔬等紧凑索引名称：15pt / 500 / 22pt。
- 底部导航：12pt / 500 / 16pt。
- 中文不得拉伸、压缩、倾斜或转成图片；字距保持 0，不使用夸张疏排。
- iOS 以系统 Dynamic Type 为实现基准：正文映射 Body，辅助信息映射 Footnote，模块标题映射 Title 3 或等效语义样式，不把上述字号写成无法缩放的固定像素。
- 支持系统字体放大；较大字体下双列内容自动降为单列，辅助信息可换行，但菜名、主要操作和安全提示不得被截断。

#### 首页尺寸与密度

- 设计画布固定 393 × 852pt，不添加设备外框。
- 页面水平内容边距统一 20px；紧凑列表可使用 16px，但同一模块不得混用。
- 搜索框与铃铛高度统一为 44pt；两者间距 10pt；铃铛及所有常用操作触控区不小于 44 × 44pt。
- 首页频道高度 44px，五项等分；选中指示线宽 20px、高 2px。
- 首屏全宽 Banner 以用户指定的 `exec-3644e6c8-f984-4602-8110-463cb88ed9a3.png` 为唯一尺寸基准。该图为 853 × 1844px，Banner 原图高度约 908px；换算到 393pt 设计宽度后，Banner 容器固定为 **393 × 420pt**。
- Banner 顶部坐标固定为 `Y = 0`，左右外边距固定为 0，后续白色内容区固定从 `Y = 420pt` 开始。
- 未经用户明确提出“修改 Banner 尺寸”，任何单屏稿、长图、分段稿、Figma 原型或代码实现都不得压缩、拉长、裁短或移动该 Banner 容器。
- Banner 不放入卡片，不加外层边框；顶部为直角，底部圆角最多 0–8px。
- Banner 后首个内容模块与图片间距 28px；模块间距 32px。
- 首屏同时出现的视觉重点只能有一个，不允许 Banner、超大标题和大型内容卡片同时争抢注意力。
- 单屏大图最多一张；后续内容图片高度通常为 104–156px，禁止连续使用接近半屏的大图。
- 首页推荐模块首屏最多展示 3 个内容入口，不用密集九宫格或重复横滑卡片。

#### 图片

- 图片优先使用真实自然光、真实材质、克制饱和度的内容素材。
- 不使用过暗影棚照、油亮高饱和商业菜品照、AI 塑料质感或无意义摆拍。
- Banner 采用 1.45–1.65:1 的移动端横向裁切，主体不得被搜索、铃铛、频道或文字遮挡。
- 同一图片只承担一个层级：主视觉、内容封面或缩略图，不同时叠加大量标题、标签和按钮。
- 图片上的文字必须由真实 UI 图层覆盖，不能烧录进位图。

#### 圆角与表面

- 普通图片圆角 8–12px；内容容器圆角 10–14px；禁止默认使用 20px 以上圆角。
- 搜索框圆角 12px，不使用胶囊形。
- 图标按钮圆角 12px；主操作按钮可以使用 12–14px，标签才允许全圆角。
- 不把每个内容块都包进白色卡片；优先使用留白、对齐和细分隔线建立层级。
- 阴影只用于浮层和固定导航，普通内容不使用悬浮阴影。

#### 原型验收

- 原型必须在 393 × 852、375 × 812 和 360 × 800 三种视口检查。
- 中文必须可选择或来自真实文本图层；出现变形、错字或不可选择即判定不合格。
- 按钮文字、图标和容器中心线误差不得超过 1px。
- 任一页面出现超过 3 种图片比例、超过 3 种圆角或超过 4 个并列决策入口，需要重新收敛。
- 高保真原型确认前不批量扩展其他页面。
- 完整推荐页可以输出长图；单张长图导致字体、图片或模块被压缩时，必须拆成两张或多张 393pt 宽的连续滚动稿。
- 连续稿只在第一张展示 Banner，后续稿按真实滚动坐标承接，不重复 Banner，也不改变已锁定模块尺寸。
- 每次视觉设计或生图前自动执行 `Superpowers/Brainstorming → pm-product-discovery → Impeccable → UI UX Pro Max → Imagegen Frontend Mobile` 路由与自检，不需要用户重复提醒。
- 每次对话回复前必须先判断当前任务命中的项目规则、工具和 skill，并在回答或执行中实际应用；不得先凭经验直接回复、事后再补 skill。
- 产品结构、需求取舍和交互问题优先使用 `Superpowers/Brainstorming` 与适用的 `pm-product-discovery` skill；C 端 UI/UX 问题必须使用 `Impeccable` 与 `UI UX Pro Max`；涉及原型图片时最后再使用 `Imagegen Frontend Mobile`。
- 每轮主动简要说明使用了哪些 skill 以及它们如何影响当前决策，不要求用户重复提醒。

### 液态玻璃边界

只允许用于：吸顶导航、底部导航、筛选底部面板、详情悬浮操作区和小型计时浮层。

- 每页最多 2–3 个玻璃区域。
- 不用于普通内容卡片和大面积背景。
- 不玻璃叠玻璃。
- 背景复杂时提高不透明度。
- 不支持模糊或设备性能不足时降级为实体暖白表面。

### 按钮和图标

统一主按钮、次按钮、文字按钮和图标按钮。

统一高度、内边距、字体、图标尺寸、图文间距、触控区、按压态、加载态和禁用态。禁止依赖原生按钮默认行高和内边距，解决当前按钮位置、文字和图标偏移问题。

图标统一 SVG 视口、描边、视觉中心和状态表现，不混用多套图标语言。

#### 首页图标系统

- iOS 优先使用 SF Symbols 语义与视觉规则，其他平台使用同名或几何等价图标，不混用粗细不同的图标库。
- 时间使用 `clock`，难度使用 `gauge.with.dots.needle.50percent`，收藏使用 `bookmark / bookmark.fill`，换一批使用 `arrow.clockwise`，查看更多使用 `chevron.right`。
- 挑选观察使用 `eye`，手感使用 `hand.tap`，饮品使用 `cup.and.saucer`，家庭使用 `person.3`，提醒使用 `bell`。
- 图标与文字同排时视觉尺寸为 16–18pt；工具按钮图标为 20–22pt；底部导航图标为 24pt。
- 非选中导航和普通工具使用轮廓符号；底部导航选中态使用填充符号和品牌色，不通过放大图标表达选中。
- 图标必须表达功能，不使用纯装饰 icon，不使用 emoji，不在每一行重复无信息价值的图标。
- 图标视觉尺寸可以不同，但必须在统一 24pt 视口内进行光学校正；所有可点击图标的实际热区不小于 44 × 44pt。
- 加载状态使用预留尺寸的骨架屏，不使用持续旋转的装饰图标。

首页与全局基础图标优先采用 SF Symbols 等效语义：搜索 `magnifyingglass`、通知 `bell`、首页 `house/house.fill`、分类 `square.grid.2x2`、菜篮 `basket`、我的 `person`、收藏 `bookmark/bookmark.fill`、换一批 `arrow.clockwise`、进入 `chevron.right`。

- 图标视觉框统一 24 × 24pt，常用交互触控区统一不小于 44 × 44pt。
- 普通状态使用 Regular 等效字重，选中状态使用 Semibold 或 Fill 变体；图标字重需要与相邻文字匹配。
- 同一导航内不得混用线框、实心、不同描边粗细或不同透视风格。
- 图标以光学中心对齐，不只依赖几何边界；图标和文字中心线误差不得超过 1pt。
- 简单图标不增加装饰底板；只有通知、计时、危险提示等需要独立触控容器时才使用 44pt 图标按钮。

## 20. 动效与反馈

动效只用于导航变化、状态反馈、内容切换和任务进度。

允许：搜索栏离场、频道选中背景移动、收藏切换、菜篮数量反馈、进度条推进、计时器变化和底部面板展开。

禁止：大量滚动入场、弹跳卡片、长期漂浮、无意义旋转和通过宽高触发布局动画。

所有提交操作包含默认、提交中、成功、失败和重复点击保护。局部操作优先在触发位置反馈，Toast 只作为辅助。

## 21. 平台适配

设计基准为 iPhone 15，393 × 852，不添加设备外框。

### iOS

- 刘海、灵动岛和 Home Indicator 安全区。
- 左侧返回手势。
- 键盘弹出和页面回弹。
- 系统字体缩放和减少动态效果。

### Android

- 不同状态栏、系统返回键和返回手势。
- 多种屏幕比例和字体缩放。
- 低性能设备玻璃降级。
- 不同输入法键盘高度。

### H5

- 浏览器地址栏动态高度。
- 固定元素遮挡。
- 输入框聚焦后的滚动。
- 不支持 `backdrop-filter` 的降级。
- 横向频道与纵向滚动手势冲突。
- 浏览器前进后退后的状态恢复。

### 后台计时与通知限制

- iOS、Android、H5 对后台计时和通知权限不同，实施前需要分别验证。
- 用户拒绝通知权限时，App 内计时仍必须可靠显示。
- H5 无法保证长期后台计时通知时，重新进入页面应根据目标结束时间恢复正确剩余时间。
- 计时器不能只依赖页面内 `setInterval`，需保存开始时间、目标结束时间和状态。

## 22. 跨页面状态

必须同步：

- 收藏：列表、详情和我的收藏。
- 菜篮：菜谱、食材、水果、饮品、角标和家庭采购清单。
- 当前家庭：首页推荐、菜篮、聚餐和忌口规则。
- 饮食档案：菜单冲突、采购清单、推荐和烹饪提醒。
- 烹饪进度：详情、烹饪页、计时通知和重新进入。

四个底部主页面分别保留频道、筛选和滚动位置。详情页返回不得重置来源页面。

## 23. 产品阶段与实施拆分

### 第一期：核心家庭饮食闭环

```text
首页 / 分类 / 统一搜索
菜谱 / 食材 / 水果 / 饮品基础内容
个人饮食档案
家庭二维码与成员
家庭聚餐与参与成员
忌口和过敏检查
生成采购清单
烹饪步骤、进度条和单计时器
收藏、历史、我的菜谱、添加菜谱和登录链路
```

### 第二期：家庭协作增强

```text
多人同步采购
多个计时器
系统推送
开饭提醒
通知中心
菜谱创建与审核
```

### 第三期：饮品与调制深化

```text
调一杯
饮品材料与正式食材关联
饮品单位换算
酒精偏好
完整调制流程
```

### 暂缓范围

- 家庭库存、现有食材、余量和保质期管理。
- 私信、群聊和实时聊天。
- 复杂到场定位。
- 第一阶段同时运行多个计时器。
- 完整调酒推荐引擎。
- 根据疾病自动提供医疗饮食方案。

本轮及已规划后续阶段均不建设“家里已有”能力，也不根据家庭库存生成推荐。

### 当前推进顺序

当前目标不是继续扩展新功能，而是在现有产品范围内先完成可用闭环，再进入统一 UI/UX 设计：

1. 审计现有页面、路由、接口和数据，确认哪些功能真实可用、部分可用或缺失。
2. 补齐首页五频道、分类、统一搜索、列表与详情、收藏、历史、家庭、菜篮、我的菜谱、添加菜谱和登录链路。
3. 补齐 Loading、Empty、Error、权限、重复点击、返回恢复、Toast 和跨页面状态同步。
4. 在功能范围和交互闭环稳定后，统一信息层级、组件、视觉、动效和多端适配。

不以新增家庭库存、买菜模式或“已有几项所需食材”推荐作为本轮完成条件。

### 工程实施拆分

每个产品阶段内部仍需拆成独立工程批次，每批单独计划、实现和验收：

1. 全局 Token、按钮、图标、导航、状态和布局基础。
2. 一级导航、首页五频道、分类目录和统一搜索。
3. 菜谱、食材、水果、饮品列表与详情闭环。
4. 菜篮、采购状态与跨页面同步。
5. 烹饪步骤、进度和计时器。
6. 个人饮食档案、家庭二维码和家庭成员。
7. 家庭聚餐、忌口检查、采购冲突和开饭提醒。
8. 收藏、历史、我的菜谱、登录、通知中心和设置。
9. 未来饮品调制能力。

每个阶段都必须覆盖 Loading、Empty、Error、重复点击、返回恢复、iOS、Android 和 H5 验收。

## 24. 核心验收标准

- 一级导航固定为首页、分类、菜篮、我的。
- 首页顶部包含推荐、菜谱、食材、水果、饮品五频道。
- 首页食材频道不展示水果和调料。
- 分类页包含菜谱、食材、水果、调料、饮品五组目录，不展示推荐内容流。
- 搜索栏向上滑动自然隐藏，频道导航吸顶。
- Banner 简单大气，不堆叠按钮和装饰。
- 所有按钮和图标位置统一，无文字或图标偏移。
- 液态玻璃局部使用且具备性能降级。
- 家庭成员的具体忌口和过敏信息可见。
- 聚餐选菜、采购和烹饪前都能检查参与成员饮食限制。
- 烹饪支持上一步、下一步、进度条和计时器。
- 创建家庭生成二维码，扫码后确认加入并填写饮食档案。
- 通知中心只承载家庭、系统和活动通知，不提供社交聊天。
- 所有关键操作有加载、成功、失败和重复点击保护。
- 不改变真实接口链路，不长期依赖硬编码假数据。
- 未识别用料不能被默认为“无忌口风险”。
- 聚餐参与成员或饮食档案变化后，菜单和采购风险能够重新计算。
- 单位无法可靠换算时不自动合并。
- 第一阶段完成从参与成员、选菜、风险检查、采购到烹饪的完整闭环。
- 家庭可见的用户菜谱可以参与聚餐、采购和烹饪，公开菜谱必须经过审核。

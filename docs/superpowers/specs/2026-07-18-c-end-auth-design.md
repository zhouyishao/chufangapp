# C 端真实鉴权设计

日期：2026-07-18  
状态：待实施  
方案：兼容迁移（B 方案）

## 1. 目标

为 C 端建立真实 JWT 身份，阻止客户端通过篡改 `userId` 冒用其他用户，同时避免一次性切换导致现有家庭、菜篮、收藏和浏览历史流程全部中断。

本阶段只建设身份基础设施和迁移首批私有接口，不调整页面视觉，不改变公开内容接口。

## 2. 核心规则

- 手机号登录成功后返回用户资料、`accessToken`、`tokenType` 和过期时间。
- Access Token 使用 `JWT_APP_SECRET` 签发，有效期 7 天。
- Token 的 `sub` 为用户 ID，并包含 `type: "app"`，避免与后台 Token 混用。
- 私有接口只信任 Token 中的用户 ID。
- 兼容期允许请求体或查询中继续携带旧 `userId`，但服务端忽略该值；若它与 Token 身份不一致，返回 403 并记录迁移问题。
- 未携带 Token、Token 失效或 Token 类型错误统一返回 401。
- 已登录但无家庭或资源权限返回 403。
- 公开首页、分类、详情、搜索和家庭邀请预览保持匿名可访问。

## 3. 服务端结构

### 3.1 Token 服务

新增独立的 App Token 模块，职责仅包括：

- 签发 App Access Token。
- 校验签名、有效期和 `type`。
- 将 `sub` 转换为正整数用户 ID。

该模块不访问数据库，便于单元测试。用户是否存在、是否禁用由鉴权中间件查询数据库确认。

### 3.2 鉴权中间件

新增 `requireAppAuth`：

1. 读取 `Authorization: Bearer <token>`。
2. 校验 Token。
3. 查询 ACTIVE 且未删除的用户。
4. 将最小身份写入 `req.appUser`。
5. 失败时返回统一 401，不泄露签名或数据库细节。

Express Request 类型扩展只包含 `id`，后续确有需要再增加字段。

### 3.3 身份兼容器

首批迁移接口通过统一函数取得当前用户 ID：

- 主来源永远是 `req.appUser.id`。
- 请求仍携带旧 `userId` 且一致时继续处理。
- 请求携带不一致的 `userId` 时返回 403。
- 迁移完成后删除旧字段校验和旧字段文档。

## 4. 登录响应

`POST /api/mobile/auth/login` 保持现有手机号登录输入，响应调整为：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "user": {
      "id": 1,
      "phone": "13800000000",
      "nickname": "小周",
      "avatar": null
    },
    "accessToken": "...",
    "tokenType": "Bearer",
    "expiresIn": 604800
  }
}
```

不增加 Refresh Token。MVP 中过期后重新登录，避免提前引入双 Token、吊销列表和刷新并发控制。

## 5. 首批迁移范围

按以下顺序迁移：

1. 家庭菜篮读取、新增、修改、删除。
2. 家庭列表、家庭详情、创建家庭、成员与邀请操作。
3. 收藏新增、列表、取消。
4. 浏览历史新增、列表、删除。
5. 个人资料读取与更新。

菜谱、食材、饮品、首页、分类和搜索保持公开。家庭邀请详情保持公开，加入家庭操作必须登录。

## 6. C 端请求流程

- 登录服务保存服务端返回的真实 Token，删除 `mobile-user-<id>` 伪 Token 生成逻辑。
- 统一请求层从登录存储读取 Token，并自动设置 `Authorization`。
- 401 时清理失效会话并跳转登录；同一时间多个 401 只触发一次跳转。
- 403 由业务页显示权限提示，不清理登录状态。
- 公开请求在未登录时不携带空 Token。
- 兼容期保留现有调用参数，待对应接口迁移完成后再逐步删除 `userId`。

## 7. 错误与边界

- Authorization 格式错误：401。
- Token 过期、签名错误、后台 Token 冒用：401。
- Token 用户不存在、已禁用或已删除：401。
- Token 用户与旧 `userId` 不一致：403。
- 已登录但不是目标家庭成员：403。
- 登录接口失败不覆盖本地已有有效会话。
- 退出登录仅清理本地 Token；服务端吊销能力不在本阶段范围。

## 8. 测试策略

### 服务端单元测试

- App Token 可以签发并还原用户 ID。
- 过期、错误密钥、错误类型 Token 被拒绝。
- Bearer Header 解析严格处理缺失和错误格式。
- Token 身份优先于兼容 `userId`，不一致时拒绝。

### 服务端接口测试

- 登录响应包含真实 Token。
- 私有接口缺少 Token 返回 401。
- 用户 A 不能通过传入用户 B 的 ID 访问 B 的数据。
- 同一家庭成员仍可共享操作家庭菜篮。
- 非家庭成员仍返回 403。

### C 端验证

- 登录后请求自动携带 Token。
- 重启应用后会话可恢复。
- Token 失效只跳转一次登录页。
- 403 不会误退出。
- 首页等公开页面未登录仍可访问。

## 9. 非目标

- 本阶段不实现短信验证码服务、微信登录、Refresh Token、设备管理和服务端 Token 黑名单。
- 本阶段不重做登录页 UI。
- 本阶段不迁移后台管理员鉴权。
- 本阶段不修改数据库 Schema。

## 10. 验收标准

- 登录返回由后端签发的有效 App JWT。
- 首批私有接口不再信任客户端 `userId`。
- 跨用户和跨家庭访问被正确拒绝。
- 现有公开内容浏览不受影响。
- 服务端测试、服务端构建和 C 端类型检查全部通过。

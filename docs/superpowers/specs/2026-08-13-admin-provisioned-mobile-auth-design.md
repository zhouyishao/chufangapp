# 后台开户制 C 端认证设计

## 目标

修复 C 端仅凭手机号即可获取登录 Token 的发布阻断漏洞。在不接入付费短信验证码的阶段，由管理员在后台创建或重置 C 端账号密码，用户使用手机号和密码登录。

## 方案选择

当前阶段采用后台开户制：

- 管理员在后台用户管理中创建账号，手机号和初始密码均为必填。
- 现有用户由管理员在编辑页设置新密码后恢复登录能力。
- C 端账号密码登录必须由后端校验 bcrypt 密码哈希。
- C 端注册、短信验证码和找回密码暂不开放，入口显示明确说明，不模拟验证码或成功状态。
- 后续开通短信服务时，在现有密码哈希模型上增加验证码注册和重置流程，不改变已存在账号的登录语义。

未采用的方案：

- 不允许按手机号自动创建用户，否则仍可接管任意手机号。
- 不使用前端本地密码作为认证凭据，本地存储不能作为服务端身份依据。
- 不实现万能验证码、固定验证码或“任意密码可登录”的临时兼容。

## 数据模型

`User` 新增可空的 `passwordHash` 字段：

- 新后台账号必须写入 bcrypt 哈希。
- 历史用户保持 `NULL`，登录时返回“账号尚未设置密码，请联系管理员”。
- API、日志、后台列表和详情均不得返回密码哈希。

迁移只新增可空字段，不删除、不覆盖历史用户，不执行破坏性数据操作。

## 接口与数据流

### C 端登录

`POST /api/mobile/auth/login`

请求：

```json
{ "phone": "13956785678", "password": "initial-password" }
```

规则：

1. 手机号和密码必须提供且格式合法。
2. 只查询已存在且未删除的用户，不再 `upsert`。
3. 用户不存在、密码错误统一返回 HTTP 401“手机号或密码错误”，避免泄露账号是否存在。
4. 历史账号没有 `passwordHash` 时返回 HTTP 403，提示联系管理员设置密码。
5. 禁用用户仍返回 HTTP 403。
6. 校验成功后签发已有 App JWT，会话有效期保持 7 天。

### 后台创建用户

`POST /api/admin/users`

- 手机号、密码必填。
- 密码最少 8 位，必须同时包含字母和数字。
- 后端生成 bcrypt 哈希，不存明文。
- 手机号重复返回 409。

### 后台编辑/重置密码

`PUT /api/admin/users/:id`

- 密码为空或未提交：不修改现有哈希。
- 提交合法新密码：覆盖为新的 bcrypt 哈希。
- 其他用户资料与状态更新逻辑保持不变。

## C 端体验

- 登录页继续保留手机号、密码输入框。
- 登录失败展示后端错误，不保存本地用户或 Token。
- 注册和忘记密码页面改为“暂未开放，请联系管理员开通/重置”，不再进入本地验证码与本地密码流程。
- 登录成功后继续使用已有会话存储、家庭、收藏、菜篮等逻辑。

## 后台体验

- 新增用户时密码必填，并显示至少 8 位、包含字母和数字的提示。
- 编辑用户时密码字段文案为“重置密码（留空不修改）”。
- 列表可用“未设置密码”状态提示历史账号是否需要管理员处理，但不显示哈希或密码。
- 后台管理员登录体系不受本次变更影响。

## 错误处理与安全

- 密码永不进入响应体、浏览器日志或操作日志。
- bcrypt 使用项目现有 `bcryptjs`，成本参数 10。
- 前后端都做基础密码规则校验，后端为最终权威。
- 登录失败不签发 Token，不覆盖已有本地会话。
- 暂不增加短信、邮件、第三方 OAuth、账号锁定或复杂风控；登录限流单独作为后续安全增强项。

## 测试与验收

自动化测试覆盖：

1. 已存在账号错误密码返回 401，不能得到 Token。
2. 正确密码返回 Token。
3. 不存在手机号不能自动创建账号。
4. 历史无密码账号返回 403。
5. 禁用账号不能登录。
6. 后台创建用户写入哈希而非明文。
7. 后台更新不传密码时保留旧哈希，传新密码时可用新密码登录。
8. API 响应不包含 `passwordHash`。
9. C 端登录请求真实提交密码。
10. 注册/找回密码页面不再模拟验证码或本地成功。

内置浏览器回归：

- 后台创建测试账号。
- C 端错误密码登录失败。
- C 端正确密码登录成功。
- 后台重置密码后旧密码失败、新密码成功。
- 注册和找回密码入口显示暂未开放说明。

## 影响范围

- 数据库：新增 `users.password_hash` 可空字段和非破坏性迁移。
- 后端：C 端登录、后台用户创建/编辑、seed。
- 后台：用户表单密码规则与账号状态提示。
- C 端：登录 API 参数、登录错误处理、注册与找回密码页面。
- 不影响内容、首页、家庭、收藏、菜篮等业务接口。

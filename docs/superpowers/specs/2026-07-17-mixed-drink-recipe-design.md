# 调饮配方详情设计

## 1. 目标

在“饮品”体系内增加统一的调饮配方结构，同时支持含酒精鸡尾酒和无酒精 Mocktail。调饮配方用于回答三个核心问题：需要什么、怎么调、缺少材料时如何替代。

普通酒水继续使用“风味 / 适饮 / 搭餐”详情结构；茶、咖啡、果饮继续使用“风味 / 搭餐 / 做法”结构。只有内容类型为 `mixed_drink_recipe` 的内容进入本设计。

## 2. 产品边界

### 本期包含

- 含酒精与无酒精调饮共用详情结构。
- 基酒或无酒精基底、辅料、冰型、杯具、装饰和工具。
- 图文或短视频制作步骤。
- 原料加入家庭菜篮。
- “开始调制”分步流程。
- 相似调饮、同基底配方和搭配菜谱。
- 含酒精内容的年龄与理性饮酒提示。

### 本期不包含

- 自动根据家中存货生成配方。
- 酒类电商购买、价格比较或库存管理。
- 用户公开评论、打分或社交分享流。
- 专业酒吧成本核算和批量配方换算。

## 3. 内容分类

调饮配方统一使用 `mixed_drink_recipe` 类型，并通过 `alcoholic` 区分：

- `alcoholic: true`：鸡尾酒，必须配置基酒、酒精度和理性饮酒提示。
- `alcoholic: false`：Mocktail，基底可为茶、咖啡、果汁、苏打水或无酒精烈酒。

频道内可以使用“含酒精”和“无酒精”作为筛选条件，但不拆成两套后台模型或前端组件。

## 4. 详情页信息架构

### 4.1 顶部主图

- 沿用详情页锁定规则：宽度随设备自适应，比例约 `852:844`。
- 左右和顶部顶满，无外边距。
- 返回、收藏、分享悬浮在主图安全区内。
- 主图必须展示完成后的饮品，不使用原料拼贴或文字海报替代。

### 4.2 标题与核心信息

显示名称、简短风味描述，以及三项最有决策价值的信息：

- 含酒精状态：`含酒精` 或 `无酒精`。
- 制作时间。
- 酒精度；Mocktail 改为甜度。

含酒精配方在核心信息下显示低干扰提示：“未成年人请勿饮酒，饮酒后请勿驾车。”

### 4.3 内容 Tab

统一为三个 Tab：

1. `配方`
2. `步骤`
3. `小贴士`

不增加“工具”Tab，工具并入配方，避免层级过多。

### 4.4 配方

配方区域使用紧凑原料卡片网格，顺序固定：

1. 基酒或无酒精基底。
2. 辅料。
3. 冰块。
4. 装饰。

每项显示图片、名称和用量。其后使用一行信息展示杯具、冰型、技法和必要工具，例如：

- 杯具：高球杯。
- 冰型：大冰块。
- 技法：摇和。
- 工具：摇酒壶、量酒器、滤冰器。

“加入菜篮”只加入可采购原料，不加入杯具和工具。重复原料按名称与规格合并。

### 4.5 步骤

- 使用纵向步骤流，每步包含序号、标题和文案。
- 每步可以配置一张图片或一个短视频，媒体不是必填。
- 需要计时的步骤显示计时入口。
- 技法首次出现时可显示一行解释，例如“摇和：加冰后快速摇动约 10 秒”。
- 最后一步必须说明装饰和出杯方式。

### 4.6 小贴士

最多优先展示三类信息：

- 原料替代：例如龙舌兰可替换为无酒精龙舌兰风味基底。
- 调整方式：减糖、降低酒精度、改变酸度。
- 失败预防：冰块融化过快、摇和不足、杯具未预冷。

不要重复步骤内容，也不展示后台运营说明。

### 4.7 继续发现

详情内容后保持三组发现内容：

- 相似调饮。
- 同基酒或同无酒精基底配方。
- 适合搭配的菜谱。

卡片沿用当前饮品详情的正方形图片与横向 2.3 张露出结构，不新增第三套卡片组件。

### 4.8 底部操作

固定双按钮等宽：

- 次按钮：`加入菜篮`，加入当前配方的可采购原料。
- 主按钮：`开始调制`，进入分步调制流程。

已加入后次按钮切换为面形选中状态和“已加入”，再次点击可移除。

## 5. 开始调制流程

沿用现有“去烹饪”流程的交互模式，但文案改为调饮语境：

- 顶部显示第几步、总步骤数和进度。
- 中部显示当前步骤媒体、文案、技法说明和计时器。
- 底部显示“上一步 / 下一步”；最后一步显示“完成调制”。
- 中途退出时保留当前步骤，再次进入可继续或重新开始。
- Mocktail 和鸡尾酒共用此流程。

## 6. 数据模型

调饮配方至少需要以下字段：

```text
id
name
cover_image
summary
alcoholic
abv
sweetness
acidity
duration_minutes
base_type
glassware
ice_type
technique
tools[]
ingredients[]
steps[]
tips[]
related_recipe_ids[]
related_drink_ids[]
status
```

`ingredients[]`：

```text
ingredient_id
name
category: base | mixer | ice | garnish
amount
unit
image
is_shoppable
substitutions[]
```

`steps[]`：

```text
order
title
description
media_type: none | image | video
media_url
duration_seconds
technique_note
```

## 7. 状态与异常

- 图片缺失：使用统一低干扰占位，不显示破图图标。
- 视频加载失败：保留步骤文案并显示“视频暂不可用”。
- 原料未关联食材库：仍可展示，但加入菜篮时以文本原料创建临时条目。
- 没有替代材料：不显示替代入口。
- 未成年人模式：隐藏含酒精调饮入口和详情。
- 重复点击加入菜篮：按钮锁定到状态更新完成，避免重复加入。

## 8. 视觉与无障碍

- 使用现有奶油侘寂背景、主色和字体 Token。
- 液态玻璃仅用于主图悬浮按钮和固定底部操作区。
- 普通内容卡不使用毛玻璃或重阴影。
- 正文不小于 14px，主要点击区域不小于 44px。
- Tab 使用 `aria-selected`，收藏和菜篮状态使用 `aria-pressed`。
- 200% 字体下内容由高度撑开，不截断用量、步骤或按钮文字。

## 9. 验收标准

- 鸡尾酒和 Mocktail 使用同一详情组件，但信息和提示正确区分。
- 鸡尾酒可以完整展示基酒、辅料、冰型、杯具、工具、装饰和步骤。
- Mocktail 不出现酒精度或理性饮酒提示。
- 三个 Tab 都有真实内容并可键盘切换。
- 加入菜篮只加入可采购原料。
- 开始调制可以完成从第一步到最后一步的流程。
- 360–430px 宽度和 100%–200% 字体下无横向溢出。
- 不改变普通酒水、茶饮、咖啡和果饮详情结构。

# 分类页当月时令推荐设计

## 目标

分类页“推荐”不再返回当前内容类型下的全部资源，而是突出当月真正适合展示的时令果蔬。

## 展示规则

- 水果页推荐只包含分类类型为 `FRUIT`、已发布、启用且 `seasonMonth` 包含当前月份的水果。
- 食材页推荐只包含分类类型为 `INGREDIENT`、已发布、启用且 `seasonMonth` 包含当前月份的蔬菜或菌菇。
- 食材页推荐排除肉禽蛋、水产海鲜、豆制品、主食和其他非果蔬内容，即使这些内容配置了月份。
- 菜谱、调料和饮品页保持现有推荐逻辑。
- 推荐排序沿用 `isRecommend DESC`、`sortOrder DESC`、`id DESC`，最多返回 20 条。
- 当月没有符合条件的内容时返回空列表，由 C 端显示现有空态；不使用全年内容或全部内容兜底。

## 月份判定

- 当前月份以服务端运行时月份为准，取值为 1–12。
- `seasonMonth` 当前主要使用逗号分隔格式，例如 `6,7,8,9`。
- 判定必须按完整月份标记匹配，不能让 1 月误匹配 10、11、12 月。
- 对历史区间格式（如 `5-10`）进行兼容解析，表示包含 5 月至 10 月。
- 空值、非法值不视为当月时令。

## 数据流

1. C 端请求分类页 `page-modules`，且筛选项为 `recommend`。
2. 服务端根据内容类型决定是否启用时令过滤。
3. 水果从 `FRUIT` 分类中筛选当月内容；食材从允许的果蔬分类分支中筛选当月内容。
4. 服务端返回最多 20 条，响应结构保持不变。
5. C 端继续复用现有推荐列表、加载态、错误态和空态。

## 验证

- 单元测试覆盖逗号月份、单月、跨年列表、区间格式、空值和非法值。
- 接口测试确认水果与食材推荐只返回当月时令内容，且数量不超过 20。
- 回归测试确认选择具体分类时不受推荐过滤影响。
- 回归测试确认菜谱、调料和饮品推荐逻辑不变。

## 影响范围与风险

- 只修改统一后端分类页推荐查询与相应测试，不改数据库结构。
- C 端接口结构不变，不需要同步改页面。
- 食材分类数据存在历史命名差异，允许的果蔬分类范围必须集中维护并有测试保护。

# 内容分类治理第一阶段设计

## 背景

内容分类已经支持 `RECIPE`、`INGREDIENT`、`FRUIT`、`SEASONING`、`BEVERAGE` 五种类型和父子关系，但后台分类管理页仍按一级扁平分类展示。当前数据还混有历史空分类、测试分类、英文供应商分类和跨内容类型分类，导致管理人员无法判断哪些分类真实服务 C 端。

## 目标

本阶段先建立“后台所见即真实数据”的管理能力，再做可恢复的数据整理：

1. 分类列表正确显示一级、二级关系和上级分类。
2. 同时显示直属内容数、包含子分类的内容数以及 C 端可展示内容数。
3. 支持按层级、启用状态和 App 展示状态筛选。
4. 统计卡片使用完整筛选结果，不再使用当前页近似值。
5. 排序只允许在同一类型、同一父级内调整。
6. 已有关联内容或子分类时禁止修改分类类型。
7. 第一阶段数据整理只隐藏或停用问题分类，不删除内容和分类。

## 非目标

- 不在本阶段重做 C 端分类页视觉。
- 不新增三级及更深分类。
- 不把菜谱场景和人群立即迁移到标签关系；只先停止新增错误分类，后续单独迁移。
- 不删除任何有关联内容的分类。
- 不新增 `description`、`remark` 数据库字段；当前无效表单字段从页面移除，后续有真实业务需求再建模。

## 分类规则

分类用于内容的唯一主要浏览归属，标签用于可交叉的属性。

- 菜谱主分类保留菜品形态或稳定栏目；`午餐`、`晚餐`、`宴客`属于场景，`儿童`、`老人`属于人群，`减脂`属于目标标签。
- 食材一级分类统一为蔬菜、菌菇、豆制品、肉禽蛋、水产海鲜、主食粮油、干货、奶制品、半成品；具体原料族群作为二级分类。
- 水果暂时使用当前 11 个有内容的浏览分组。
- 调料以当前 18 个有内容的细分类为有效数据，旧的空分类隐藏。
- 饮品以中文分类为正式分类；英文供应商分类必须先迁移内容，再隐藏。
- `时令水果`、`时令蔬菜`、`应季食材`不作为静态分类，时令性由 `seasonMonth` 动态判断。

## 后端设计

### 分类列表

`GET /api/admin/categories` 增加可选查询参数：

- `level=1|2`
- `isPublish=true|false`

每条分类返回：

- `level`
- `directContentCount`：直属且未删除的内容数。
- `descendantContentCount`：本分类和所有子分类的未删除内容数。
- `publicContentCount`：本分类和所有子分类中符合 C 端公开条件的内容数。
- `childCount`

分页统计额外返回当前筛选条件下的 `summary`：总数、一级数、二级数、启用数、停用数、App 展示数、App 隐藏数和无公开内容数。

为了兼容现有调用，保留 `relatedCount`，值等同 `directContentCount`。

### 写入保护

- 有直属内容、后代内容或子分类时，不允许修改分类类型。
- 上级分类必须同类型。
- 最多允许两级；二级分类不能再作为新分类的父级。
- 仍保留循环引用检查。

### 排序

新增同级排序接口，接收同一类型、同一父级下的完整分类 ID 顺序，由事务写入连续排序值。列表页不再通过两个并行 `PUT` 交换当前分页记录的排序值。

## 后台页面设计

- 分类类型仍使用五个类型页签。
- 层级筛选开放“全部、一级、二级”。
- 增加“App展示”筛选。
- 表格层级列显示“一级”或“二级”；分类名称前使用缩进展示二级项，并显示上级分类。
- 内容数量展示为“公开 / 总计”，悬停或辅助说明区分直属和含子级。
- 状态列拆分为“启用状态”和“App展示”。
- 统计卡片读取接口 `summary`。
- 排序按钮只在当前类型、同一父级的完整列表中启用；跨分页或“全部类型”视图不提供排序。
- 编辑页删除没有持久化能力的“分类说明”和“备注”。
- 编辑已有引用的分类时锁定“分类类型”。

## 数据整理

数据操作使用事务脚本，先输出预览，再执行事务。脚本只把“公开内容子树为 0”的问题分类设为 App 隐藏，不物理删除，也不改变关联内容状态。

第一批候选：

- 测试/外语分类：`Chicken`、`E2E菜谱`、`E2E食材`；仅在公开内容子树为 0 时隐藏。
- 调料旧空分类：`基础调味`、`酱料`、`香辛料`、`复合调味`、`腌制调料`、`烘焙调料`、`基础调料`、`调料`。
- 食材错误或空分类：`水果`、`酒水饮品`、`应季食材`、`时令蔬菜`、`E2E食材`、`菌菇类`、`干货`、`生禽`、`水产`。
- 菜谱和饮品中公开内容子树为 0 的分类先隐藏，后续补充公开内容时可重新展示。
- `Ordinary Drink` 有 3 条公开内容，本阶段不自动迁移或隐藏；中文映射作为下一阶段的数据本地化任务。

水果已隐藏的 8 个历史分类保持隐藏，不删除。

## 种子数据

调整 `server/prisma/seed.ts`，不再创建已废弃的空分类、测试分类或英文供应商分类。种子只维护正式分类；重复执行不得重新发布已经人工隐藏的历史分类。

## 错误处理

- 非法层级、跨类型父级、类型变更冲突返回 HTTP 422 和中文业务提示。
- 排序列表不完整、包含不同类型或不同父级时返回 HTTP 409，不进行部分更新。
- 数据整理脚本遇到找不到分类或发现公开内容数量不为 0 时整体回滚。

## 测试与验收

1. 后端契约测试覆盖层级筛选、发布筛选、统计、子树数量、公开内容数量和写入保护。
2. 后台契约测试覆盖真实层级展示、App展示筛选、统计字段和同级排序限制。
3. 类型修改冲突、三级分类、跨父级排序都必须失败且数据库不产生部分更新。
4. 数据整理前后运行只读审计：问题分类不再发布，正式分类内容数不减少。
5. 验证 C 端分类接口仍只显示有公开内容的分类。

## 实施顺序

1. 后端测试与分类统计/校验实现。
2. 后台测试与分类管理页修正。
3. 种子分类收敛。
4. 生成数据整理预览并核对。
5. 执行可恢复的数据隐藏/迁移。
6. 运行后台、后端和 C 端分类回归验证。

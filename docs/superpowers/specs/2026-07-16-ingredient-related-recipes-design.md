# 食材详情相关菜谱模块设计

## 目标

在食材详情页增加与当前食材相关的菜谱入口，让用户在了解挑选、保存和食用方法后，可以继续进入菜谱详情。模块不改变已锁定的主图、详情信息、Tab 和底部菜篮结构。

## 页面结构

- 模块位于食材详情三个 Tab 内容之后、底部固定操作栏之前。
- 模块常驻显示，不跟随“怎么挑 / 怎么放 / 怎么吃”切换而隐藏。
- 标题使用动态食材名称，例如“番茄可以这样做”。
- 右侧不放“查看更多”，通过横向列表最后一张“更多菜谱”卡进入菜谱列表。
- 删除“怎么吃”面板中现有的重复“适合做”入口，只保留食用建议。

## 卡片设计

- 横向滑动，一屏露出约 2.3 张，提示仍有后续内容。
- 菜谱图片使用正方形，图片与卡片顶部、左右边缘顶满。
- 图片下只保留菜谱名称和“时间 · 难度”，不增加描述、标签或菜篮按钮。
- 使用真实菜谱图片；卡片点击进入对应菜谱详情。
- 最后一张使用同尺寸的“更多菜谱”入口，不使用单独箭头或悬浮按钮。

## 示例内容

1. 番茄炒蛋 — 15 分钟 · 简单
2. 番茄炖牛腩 — 90 分钟 · 适中
3. 番茄虾仁汤 — 25 分钟 · 简单
4. 更多番茄菜谱

## 交互与状态

- 横滑使用原生滚动和轻量滚动吸附。
- 点击菜谱卡进入对应菜谱详情。
- 点击“更多菜谱”显示进入番茄相关菜谱列表的反馈；原型阶段不新增正式列表页面。
- 卡片按压提供轻微缩放反馈，键盘焦点清晰可见。
- 200% 字体下卡片宽度扩大，标题允许两行，不能截断主要信息。

## 验收标准

- 模块不出现在菜谱、水果、饮品、酒水和调料详情页。
- 切换任意食材详情 Tab 后，模块始终存在且内容不重复。
- 393px 宽度显示约 2.3 张卡片，图片保持正方形。
- 360–430px 宽度及 100%–200% 字体下无横向页面溢出。
- 菜谱卡均可点击，原型控制台无 JavaScript 错误。
- 不修改接口、数据库和正式 C 端页面。

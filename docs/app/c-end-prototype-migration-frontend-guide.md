# 正式 C 端原型迁移前端开发执行手册

## 1. 文档用途

本手册面向负责 `frontend/` 的前端开发者，用于把已经确认的交互原型逐页迁移到正式 C 端。

开发者不需要重新翻阅完整产品讨论，但必须同时使用：

1. 本执行手册：决定前端具体怎么拆任务、写组件和验收。
2. [《正式 C 端原型迁移实施计划》](../superpowers/plans/2026-07-24-c-end-prototype-migration.md)：决定阶段、边界和发布门槛。
3. [交互原型](../prototypes/home-feed-interactive/index.html)：决定已经确认的页面结构、尺寸、信息层级和交互。
4. [全局 UI 规则](../design/ui-rules.md) 与 `frontend/src/styles/global.scss`：决定安全区、字体和 Token。
5. 当前 `frontend/src/services/`：保留已经接通的真实接口、鉴权、上传和业务行为。

本手册不是新设计稿，也不授权重新设计已确认区域。开发目标是：

```text
原型视觉与交互意图
+ 正式 C 端真实数据和真实权限
+ 可维护的 uni-app 组件
+ 完整状态与验收证据
```

## 2. 来源优先级

出现冲突时按以下优先级处理：

1. 用户在交互原型中最后确认的结构和锁定尺寸。
2. 根目录 `AGENTS.md`。
3. 本手册。
4. 正式迁移实施计划。
5. `docs/design/`、`docs/app/` 和 `docs/backend/`。
6. 当前正式 C 端代码。

当前代码只作为功能、接口和数据处理证据，不作为视觉标准。不能因为旧页面已经存在，就保留与原型冲突的布局。

### 2.1 技术栈冲突说明

当前可执行项目由 `frontend/package.json` 和现有 `.vue` 页面确认，技术栈为：

- uni-app；
- Vue 3；
- TypeScript；
- SCSS；
- `uni.*` 路由、存储、请求和媒体能力。

根目录 `AGENTS.md` 已明确正式 C 端继续使用现存 uni-app + Vue 3。`frontend/AGENTS.md` 中的 React、TailwindCSS 和 shadcn/ui 描述与当前可执行代码不一致，本次迁移不得据此重写框架。

开发者禁止：

- 把正式 C 端迁移为 React；
- 新增第二套路由系统；
- 为单页引入新 UI 框架；
- 把原型 HTML、CSS、JavaScript 整页复制进 Vue 页面；
- 为追求视觉一致而绕过已有服务层或真实接口。

## 4. 单页迁移标准流程

每个页面严格执行以下顺序，不得先写完整样式后再补接口：

### 步骤 1：登记页面

在任务记录中写明：

- 正式路由；
- 原型视图和截图；
- 当前页面文件；
- 服务函数；
- 页面 DTO；
- 锁定区域；
- 允许调整区域；
- 已知接口缺口。

### 步骤 2：保护现有功能

先验证当前页面已有：

- 登录态；
- 分页；
- 收藏；
- 菜篮；
- 家庭权限；
- 上传；
- 返回行为；
- 错误处理。

将需要保留的能力列出来，禁止视觉迁移时删除。

### 步骤 3：冻结页面 DTO

页面模板只能消费页面 DTO。历史字段、空值、旧 URL 和接口差异统一在 `frontend/src/services/` 适配。

禁止在模板中出现：

```ts
item.cover || item.coverUrl || item.image || item.imageUrl
```

应在服务层统一为一个字段：

```ts
type ContentCardDTO = {
  id: string
  title: string
  coverUrl: string
}
```

如果接口缺字段：

1. 记录接口契约缺口；
2. 暂停依赖该字段的视觉实现；
3. 单独修改 `server/` 和前端类型；
4. 不使用 mock、随机图或临时常量绕过。

### 步骤 4：先建结构，再做视觉

按照原型确定：

- 页面区域顺序；
- 图片比例；
- 横滑/纵向布局；
- 固定层和滚动层；
- 操作入口位置；
- 内容折叠规则。

结构通过后再使用全局 Token 调整字体、颜色、间距和圆角。

### 步骤 5：补齐页面状态

至少实现：

- Loading；
- Empty；
- Error；
- Retry；
- Loaded；
- Pagination end；
- 无权限；
- 内容已下架；
- 图片或视频失败。

### 步骤 6：接入真实交互

页面所有可点击元素必须：

- 跳转到真实路由；
- 调用真实服务；
- 有按压或提交反馈；
- 防重复点击；
- 成功后同步本地状态；
- 失败后允许重试。

### 步骤 7：截图和流程验收

完成后提交：

- 393px 与原型对照截图；
- 360、375、430px 截图；
- 200% 字体截图；
- 正向流程结果；
- 至少一个错误或空态；
- 构建和类型检查结果。

### 步骤 8：单页提交

一个页面或一个共享组件形成一个语义提交。不要把多个未验收页面塞进同一提交。

## 5. 正式前端目录职责

| 目录 | 职责 |
|---|---|
| `frontend/src/pages/` | 路由页面、页面状态、页面级编排 |
| `frontend/src/components/app/` | AppShell、安全区、图标、通用操作 |
| `frontend/src/components/home/` | 首页专用头部和底部导航 |
| `frontend/src/components/home-modules/` | 后台驱动的首页内容模块 |
| `frontend/src/components/category-modules/` | 分类页配置模块 |
| `frontend/src/services/` | 请求、鉴权、DTO 映射、资源 URL、兼容层 |
| `frontend/src/types/` | 页面和业务类型 |
| `frontend/src/styles/global.scss` | 唯一全局 Token 与全局基础样式入口 |

### 5.1 页面职责

页面允许处理：

- 路由参数；
- 页面生命周期；
- Loading/Empty/Error；
- 组合共享组件；
- 调用服务；
- 交互后的页面状态。

页面不允许处理：

- 拼接 API 根地址；
- 直接调用 `uni.request`；
- 兼容多套后端字段；
- 持久保存临时文件 URL；
- 判断服务端权限；
- 定义另一套字体和颜色系统。

### 5.2 服务层职责

统一复用：

- `apiRequest`：请求、Token 和 401 处理；
- `resolveAssetUrl`：资源地址；
- `auth-session.ts`：登录会话；
- `basket.ts`：菜篮业务；
- `family.ts`：家庭业务；
- `file-upload.ts`：上传；
- `profile.ts`：个人资料；
- `my-recipes.ts`：个人菜谱；
- `public-api.ts`：公开内容和页面 DTO。

当前 `basket.ts`、`family.ts` 仍存在把 `userId` 传入兼容接口的实现。页面不得新增或暴露 `userId` 参数；该兼容逻辑只能留在服务层，并在 API 契约阶段改为完全使用 JWT `sub`。

## 6. 共享组件清单

迁移页面前先收敛或补齐以下组件。已有组件可修改，不为同一能力建立第二套组件。

| 组件能力 | 建议归属 | 必须支持 |
|---|---|---|
| 安全区页面容器 | `components/app/` | 顶部、底部安全区，固定操作区占位 |
| 通用顶部操作 | `components/app/` | 返回、收藏、分享，统一尺寸 |
| App 图标 | `components/app/app-icon.vue` | 线性/面形两种状态、统一基线 |
| 底部导航 | `components/home/home-tab-bar.vue` | 四项、当前面形、未选中线性、无下划线 |
| 搜索与铃铛 | `components/home/` | 同一行、铃铛独立、滚动隐藏搜索 |
| 频道导航 | `components/home/` | 推荐/菜谱/食材/水果/饮品、吸顶稳定 |
| Banner | `components/home/` | 多图、焦点、后台跳转、加载失败 |
| 横滑容器 | `components/app/` 或业务组件 | 右侧露出、滚动恢复、无滚动条 |
| 菜谱卡 | 共享内容组件 | 正方形图、标题、时长、难度、收藏 |
| 物品卡 | 共享内容组件 | 正方形图、月份、约价格/斤、菜篮状态 |
| 左图右文卡 | 共享内容组件 | 当季/挑选/关联内容，标签右上，无箭头 |
| 详情主图 | 共享详情组件 | 满宽、焦点、返回/收藏/分享 |
| 详情底部操作 | `content-detail-actions.vue` | 两个等宽按钮、安全区、提交态 |
| 内容状态 | `components/app/` | Skeleton、Empty、Error、Retry、End |
| Toast/确认/底部弹层 | `components/app/` | 安全区、焦点、关闭、重复点击保护 |
| 媒体 | `components/app/` | 图片失败、视频封面、播放失败、懒加载 |

共享组件只解决稳定重复问题。不要为了“组件化”把每个两行文字都拆成组件。

## 7. 全局视觉实现规则

### 7.1 字体

只使用 `frontend/src/styles/global.scss` 已有字体 Token：

- Hero：28/600/36；
- 页面标题：24/600/32；
- 详情标题：22/600/30；
- 模块标题：18/600/26；
- 卡片标题：17/600/24；
- 列表标题：16/500/24；
- 正文：15/400/24；
- 描述：14/400/22；
- 辅助：13/400/20；
- 标签：12/500/18；
- 底部导航：11/500 或 600/14。

禁止：

- 页面内自行定义字体家族；
- 正文小于 14px；
- 大量使用 700；
- 使用纯黑 `#000`；
- 通过 `transform: scale()` 缩小文字。

### 7.2 颜色

- 页面背景：`#F5F1EA`；
- 主要表面：`#FFFDFC`；
- 主文字：`#2F2F2F`；
- 主色：`#7A8B6F`；
- 辅助文字：使用全局 Token；
- 橙色只用于少量提醒、过敏和状态点。

普通内容卡禁止大面积毛玻璃、彩色渐变和重阴影。

### 7.3 间距和密度

- 使用统一的 4、8、12、16、20、24、32 间距节奏并收敛为全局 Token。
- 普通页面左右内容边距默认 16px。
- 首页 Banner 和详情主图是例外：左右、顶部顶满。
- 触控区域至少 44×44px；图标视觉尺寸可小于点击区域。
- 用户已明确不接受大面积空白和“大按钮挤占内容”，因此不得机械套用网页端大留白。
- 卡片信息只保留完成判断和操作所需内容，描述按原型限制行数。

### 7.4 圆角、边框和阴影

- 卡片圆角、图片圆角和按钮圆角分别使用统一 Token，不得每页随机设置。
- 图在卡片顶部时，图片上边圆角跟随卡片；图片底部不单独加圆角。
- 图片与卡片上、左、右边缘顶满，不留白边。
- 优先用背景色、间距和弱分隔建立层级；不使用通用厚边框。
- 阴影仅用于底部导航、弹层或确有层级的浮层。

### 7.5 液态玻璃

只允许用于：

- 底部导航；
- 必要的吸顶或悬浮操作；
- 底部弹层。

普通列表、内容卡、推荐模块和详情正文禁止使用。

## 8. 锁定尺寸与响应式

### 8.1 设计基准

- 设计宽度：393pt；
- 首屏参考高度：852pt；
- iPhone 15 顶部和底部安全区只用于设计校验；
- 正式代码使用 `env(safe-area-inset-*)`，不写死 59px 或 34px。

### 8.2 首页 Banner

```text
393px 宽度：393×420
其他宽度：aspect-ratio: 393 / 420
```

禁止所有设备都写死 `height: 420px`。

### 8.3 详情主图

```text
设计参考：约 852×844
展示方式：满宽、顶部顶满、左右顶满
裁切：object-fit / aspectFill
焦点：优先使用后台 imageFocus
```

### 8.4 正方形图片

以下图片使用 1:1：

- 首页横滑菜谱卡；
- 时令果蔬；
- 分类双列食材、水果、饮品、调料；
- 食材清单小卡；
- 我的菜谱横滑卡。

必须由容器比例保证正方形，不依赖原图尺寸。

### 8.5 验收宽度

- 360px；
- 375px；
- 393px；
- 430px；
- 字体 100%、120%、150%、200%。

验收结果必须满足：

- 无页面横向滚动；
- 标题、按钮和图标不重叠；
- 固定底部区域不遮挡最后一项；
- 200% 字体下卡片由内容撑高；
- 主要操作仍可见、可点击。

## 9. 一级页面执行规格

### 9.1 首页 `pages/index/index`

原型：`#homeScroll`。

锁定结构：

1. Banner 满宽并置于顶部。
2. 搜索框和独立铃铛同一行。
3. 频道位于搜索框下：推荐、菜谱、食材、水果、饮品。
4. 上滑后搜索框隐藏，频道垂直吸顶；禁止横向滑入或滑出动画。
5. 频道切换同时切换 Banner 和内容。
6. 推荐流从时令果蔬开始，后续模块使用至少五种构图。
7. 标题右侧统一使用“查看更多”，不得使用无意义小标题。
8. 菜谱横滑卡一屏约 2.5 张，正方形图片。
9. 底部四项导航保持固定规范。

数据：

- `getHomeTopNavs`；
- `getHomeHeroBanners`；
- `getHomeModules` 或冻结后的页面 DTO。

不得回退到静态推荐。请求竞态必须保证旧频道响应不能覆盖新频道。

### 9.2 分类 `pages/ingredients/index`

原型：`#categoryView`。

锁定结构：

1. 顶部搜索。
2. 大分类：菜谱、食材、水果、饮品、调料。
3. 左侧二级分类。
4. 右侧内容。
5. 菜谱用单列紧凑列表。
6. 食材、水果、饮品、调料用双列正方形卡。
7. 不显示额外胶囊筛选导航。

分类页是底部“分类”的宿主页。`pages/recipes/index` 保留为菜谱完整列表或兼容深链，不再建立另一套分类首页。

### 9.3 菜篮 `pages/basket/index`

原型：`#basketView`。

锁定结构：

1. 顶部保留系统安全区空间，不绘制模拟状态栏。
2. 显示当前家庭名称和下拉箭头。
3. 右上为扫一扫入口。
4. 食材/菜谱分段控制紧凑，不使用占据大面积的按钮。
5. 家庭口味摘要紧凑展示忌口、喜欢、过敏。
6. 食材视图合并相同物品；菜谱视图可展开。
7. 点击食材名称弹出与详情页一致的挑选内容。

家庭切换、勾选、数量、删除、完成采购和提醒必须调用真实服务。

### 9.4 我的 `pages/mine/index`

原型：`#mineView`、`mine-393x852.png`、`mine-full-393.png`。

锁定结构：

1. 头像、昵称、简介、编辑入口。
2. 共享信息行保持已确认长度。
3. 家庭区只保留管理、口味、家庭码三个入口。
4. 我的菜谱横滑展示约 2.5 张。
5. 点击“我的菜谱”标题进入列表；卡片进入详情；无三点菜单。
6. 收藏与最近浏览为紧凑并列入口。
7. 无草稿、主页壁纸和顶部齿轮。

## 10. 列表、详情和流程页面规格

### 10.1 菜谱列表 `pages/recipes/index`

- 使用正方形小卡尺寸，不使用原来的大卡。
- 显示名称、时长、难度和收藏。
- 需要加菜篮时，菜篮按钮与收藏不挤在同一狭窄列。
- 列表返回后恢复滚动位置。

### 10.2 五类详情

| 路由 | 必须展示 |
|---|---|
| `pages/recipe-detail/index` | 食材、步骤、小贴士、家庭忌口、相关推荐 |
| `pages/ingredient-detail/index` | 时令、约价格/斤、挑选、保存、吃法、相关菜谱 |
| `pages/fruit-detail/index` | 时令、约价格/斤、挑选、保存、吃法、相关菜谱 |

## 11. 路由和返回栈

统一使用 `uni.navigateTo`、`uni.navigateBack`、`uni.reLaunch` 的既有策略，不自行操作浏览器 History。

必须验证：

- 四个底部一级页切换不重复堆叠页面；
- 列表进入详情后返回原列表和滚动位置；
- 首页横滑模块进入详情后返回原频道和横滑位置；
- 搜索结果进入详情后返回原关键字和结果；
- 通知、分享、扫码和深链可直接进入目标；
- Token 失效跳转登录后恢复原目标；
- 已下架或不存在内容不会进入空白页；
- 不返回已被替换的旧页面。

路由参数必须在页面入口解析和校验。缺少 `id`、非法 `id` 和错误内容类型都进入错误态。

## 12. 状态与交互规范

### 12.1 状态呈现

| 状态 | 前端行为 |
|---|---|
| Loading | 与最终布局接近的骨架，不用纯文字占满页面 |
| Empty | 说明当前为空并给出合理下一步 |
| Error | 说明失败原因，提供重试 |
| 401 | 统一清理会话并跳登录，保留回跳目标 |
| 403 | 显示无权限，不伪装为空 |
| 404/下架 | 显示内容不可用并提供返回 |
| Pagination end | 低干扰结束提示，不持续显示加载动画 |
| Media error | 低干扰占位，保留文字和操作 |

### 12.2 收藏和菜篮

- 收藏按钮独立拦截点击，不触发卡片跳转；
- 未收藏为线性图标，已收藏为面形；
- 未加入菜篮为线性，已加入为面形；
- 乐观更新失败必须回滚；
- 重复点击不能产生重复记录；
- 菜篮状态以当前家庭为作用域。

### 12.3 按钮

- 点击区域至少 44px；
- 有按压反馈；
- 提交中禁用重复点击；
- 图标和文字水平对齐；
- 图标不得单独占据无意义的一行；
- 详情底部两个按钮等宽、等高；
- 危险操作必须确认。

## 13. 媒体实现

- 页面持久数据使用文件 ID 对应的正式 URL，不保存 `blob:` 或临时上传 URL。
- 所有图片通过统一资源函数解析。
- Banner 首图可优先加载；其他图片延迟加载。
- 卡片图片声明比例，避免加载跳动。
- 图片需要真实替代文本或等价无障碍说明。
- 视频不自动播放。
- 视频加载失败不阻塞文字步骤。
- 上传组件必须说明格式、大小和数量：
  - 图片 JPG/PNG/WebP；
  - 头像至少 512×512，最大 5MB；
  - 视频 MP4/MOV/WebM，大小和时长使用服务端正式限制；
  - 支持进度、失败重试、删除、替换和排序。

## 16. 禁止事项

- 不修改冻结原型。
- 不先做静态页面再“以后接接口”。
- 不在页面中保留 mock 兜底。
- 不硬编码用户 ID、家庭 ID、内容 ID、图片 URL 或价格。
- 不使用临时 URL 作为持久值。
- 不在多个页面复制相同的卡片、状态或底部导航。
- 不通过增加大圆角、大阴影和玻璃效果制造“高级感”。
- 不擅自调整 Banner、详情主图、顶部频道和底部导航锁定尺寸。
- 不恢复用户已删除的功能：社交消息、主页壁纸、草稿、库存、独立买菜模式。
- 不一次重写整端。
- 不删除旧路由，直到新页面通过真实数据和回归验收。

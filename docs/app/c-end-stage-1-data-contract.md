# C 端阶段 1：基础数据契约

日期：2026-07-18  
依据：`c-end-prototype-implementation-audit-2026-07-18.md`

## 目标

阶段 1 先固定会影响全部正式页面的数据边界，再进入首页、分类和详情页 UI 重构。执行顺序为：数据库 → API → 后台 → C 端 → 联调。

## 1. 家庭共享菜篮（已完成）

### 读取范围

- 个人菜篮：`userId + familyId = null`。
- 家庭菜篮：`familyId`，读取前校验当前用户是该家庭的 ACTIVE 成员。
- 家庭条目的 `userId` 暂时表示创建人，不再作为家庭读取条件。

### 修改范围

- 个人条目仅创建人可修改或删除。
- 家庭条目由该家庭任一 ACTIVE 成员共同维护。
- 非家庭成员不能读取、修改或删除家庭条目。

### 当前接口

- `GET /api/mobile/basket-items`
- `POST /api/mobile/basket-items`
- `PUT /api/mobile/basket-items/:id`
- `DELETE /api/mobile/basket-items/:id`

### 身份迁移状态

菜篮接口已从 App Token 取得当前用户。兼容期继续接收旧 `userId`，但仅允许它与 Token 用户一致；不一致返回 403。数据库现有 `userId` 继续表示创建人，后续统一命名为 `createdByUserId` 时再做非破坏性迁移。

## 2. C 端真实鉴权（基础设施已完成）

- 手机号登录已返回 access token、7 天有效期和用户资料。
- 菜篮已从服务端会话取得用户 ID；收藏、历史、家庭和个人资料按后续业务批次迁移。
- 401：登录失效；403：已登录但无资源权限；404：资源不存在。
- C 端已统一处理 Token 存储、请求注入和失效清理；旧伪 Token 会在下次同步时自动升级。
- 兼容期可读旧 `userId`，但服务端必须以 Token 身份为准并拒绝冒用。

## 3. 个人偏好与家庭共享

- 数据归属个人，不再只保存一条家庭聚合偏好。
- 类型固定为：喜欢、忌口、过敏。
- 每条偏好包含是否共享给家庭。
- 家庭聚会、采购和烹饪提醒只聚合当前家庭成员已共享的信息。
- 成员备注只表示家人称呼，不承载忌口或喜好。

## 4. 统一上传

- 使用同一上传接口承载个人头像、家庭头像、菜谱封面、步骤图片和步骤视频。
- 返回稳定资源 URL、媒体类型、宽高、时长和文件大小。
- 前后端同时校验格式、大小、数量；失败支持重试，删除需删除未提交的临时资源。
- 上传规格由存储方案确认后写入统一常量，后台和 C 端禁止各写一套。

## 5. 饮品结构化数据

- 基础饮品与可调制饮品使用明确类型区分。
- 可调制饮品返回基酒、辅料、用量、装饰、器具、步骤和计时信息。
- 详情页根据类型显示“加入菜篮”或“去制作”。
- 后台表单、API DTO、数据库字段和 C 端制作步骤共用同一字段定义。
- 旧数据中解析 `description` JSON 的逻辑只保留迁移兼容期。

## 阶段 1 验收顺序

1. 家庭共享菜篮（完成）。
2. C 端真实鉴权基础设施与菜篮迁移（完成）。
3. 个人偏好与共享范围。
4. 统一上传。
5. 饮品结构化 DTO 与制作数据。

五条完成后再开始正式首页、分类、详情页组件迁移，避免页面先完成后因字段和权限变化返工。
